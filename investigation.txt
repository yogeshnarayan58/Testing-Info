I added the publish-failure logging to confirmPublish() in survey-builder.page.ts. It is the only method touched, and I ran nothing.

Listener: after the confirm-publish button is visible and before the click, confirmPublish() registers a response listener on the underlying Playwright page. It reaches the page the same way other methods in the file do, through (BasePage as any).page.
Matching: the first response whose URL contains /api/v1/publish removes the listener, so it only ever reacts once.
Logging: if that response's status is 400 or higher, it prints three lines:
Publish request failed with status <code>
Publish request post data: …, cut to 3000 characters
Publish response body: …, cut to 2000 characters
Safety: reading the status and bodies is inside a try/catch that swallows errors, so logging can't fail the test. Responses below 400 print nothing.
Click failure: if the click itself throws, the listener is removed before the error is rethrown, so none is left behind.
The rest of the method, including the return value and error message, is unchanged. If the click succeeds but no matching response ever arrives, the listener stays on the page until the page closes. That is harmless, but it is not removed.
