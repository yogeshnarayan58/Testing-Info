## 3. Is `niq-report-card` a design-system component? What does it do internally?

Yes. It's imported via `CardModule` from `@nielseniq/athena-core` (see
`my-assets-page.component.ts` imports: `CardModule, IconModule, ButtonModule, ... from '@nielseniq/athena-core'`).
Its compiled source was located in
`node_modules/@nielseniq/athena-core/fesm2022/nielseniq-athena-core.mjs`
(class `ReportCardComponent`, `selector: 'niq-report-card'`).

**Its own template root** (simplified from the compiled bundle):
```html
<div class="card-container"
     [class.one-third-width]="variant() === 'one-third'"
     [class.half-width]="variant() === 'half'"
     [class.full-width]="variant() === 'full'"
     ... (more size/variant classes) ...>
  <div class="tick" *ngIf="selected()"> ... </div>
  <div class="card-header">
    <ng-content select="[card-header]"></ng-content>
    <niq-icon *ngIf="variant() === 'multi'" (click)="collapsed = !collapsed" ...></niq-icon>
    <div class="card-title" (dblclick)="onHeaderDoubleClick()"> ... </div>
  </div>
  <!-- body/content area where our [card-body] projected content lands -->
  ...
</div>
```

**Host bindings / listeners on the component itself:**
```
host: { listeners: { "input": "onInputChange($event)" } }
```
That's the **only** native event the component itself listens for on its
host — and it's for the inline header-rename textfield feature, unrelated to
whole-card clicks. There is **no** `(click)` host listener, no
`stopPropagation()`/`preventDefault()` anywhere in `ReportCardComponent`'s own
code, and **no dedicated `@Output()` for "card clicked"** (its only output is
`headerChangeEvent` aliased `headerChange`, for the rename feature).

**Conclusion — does it intercept or block the click?** No. Because the
component doesn't attach its own click listener or call
`stopPropagation()`/`preventDefault()` anywhere in its template or class, a
native `click` fired anywhere inside the projected `[card-body]` content (the
icon, the title text, etc.) bubbles normally, through `card-container`, up to
the host custom element `<niq-report-card>` — which is exactly where our own
`(click)="navigateToSelectPanelist()"` binding lives. Angular attaches that
listener directly to the host DOM node, so it fires correctly on a real click
anywhere in the card. **This is not the cause of any bug** — the click
mechanism itself works as intended.

## 4. Does it render as a real clickable/native element, or just CSS styling?

**Just CSS styling on a plain `<div>` — no built-in clickable semantics.**

- The component's real DOM root is `<div class="card-container" ...>` — not
  a `<button>`, not an `<a>`, and it has no `role="button"`, no `tabindex`,
  and no keyboard handling (Enter/Space) for the whole-card click. The only
  keyboard handling in this component (`onElementKeydown`) is attached to the
  small chevron `<niq-icon>` used for the "multi" collapse/expand variant —
  unrelated to whole-card activation.
- Checked the component's own compiled styles for `cursor:pointer`: it is
  applied **only** to `.card-header>niq-icon` (i.e. that same
  collapse/expand chevron), **not** to `.card-container` as a whole. So
  hovering over most of the card (the icon/title/subtitle area used by
  "Start from scratch", etc.) does **not** show a pointer cursor by default —
  there's no visual affordance from the design system that the card is
  clickable; that relies entirely on whoever consumes it (this repo) adding
  `(click)` and any desired styling themselves.
- Net effect in plain terms: `niq-report-card` is a purely presentational
  container. It happens to work as a click target because native DOM click
  events always bubble regardless of the tag being a `<div>` vs a `<button>`,
  and Angular's `(click)` binding on the host catches that bubbled event —
  but it provides none of the accessibility/semantic guarantees a real
  `<button>` would (keyboard activation, `role`, focus styling, pointer
  cursor). That's a UX/accessibility gap in the design-system component
  itself, not something wrong in this repo's usage, and not something that
  would break a Playwright `.click()` on the `data-test-id` locator.

## Summary

| Question | Finding |
|---|---|
| Where does `(click)` live? | Directly on the `<niq-report-card>` host tag in `my-assets-page.component.html` — same element as `data-test-id`. |
| Does `niq-report-card` intercept/stop the click? | No — no host click listener, no `stopPropagation`/`preventDefault` anywhere in the component; native click bubbles through normally. |
| Is it a real interactive element (button-like)? | No — root DOM node is a plain `<div class="card-container">`, no `role`, no `tabindex`, no keyboard activation for the whole card. |
| Does it apply `cursor:pointer` to the whole card? | No — only to the small chevron icon used in the "multi" variant, not to the card body/container. |
