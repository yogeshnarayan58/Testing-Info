# Reporter Comparison

This document contains the standalone comparison of the survey-mod Grafana reporter against `disc-fe-omnishopper-ui-automation`'s Grafana reporter. Both reporter files and configuration files were read fresh from disk. No external API was called.

## Our Reporter

File: `e2e/playwright/reporters/grafana-reporter.ts`

```ts
import { Reporter, Suite, TestCase, TestResult } from '@playwright/test/reporter';
import { FullConfig } from "@playwright/test";
import * as path from 'path';
import { config } from '../../utils/configurationDetails';
import { PostgresActions, CustomReporterOptions, CommonReporterUtils } from "@gfk/gta";


class GrafanaPlaywrightReporter implements Reporter {

    private areaId: number | undefined;
    private domainId: number | undefined;
    private teamId: number | undefined;
    private options: CustomReporterOptions;
    private projectId: number | undefined;
    private environmentName: string;
    private commonReporterUtils: CommonReporterUtils | undefined;
    private postgresActions: PostgresActions;
    private previousTestCaseId: string | null | undefined;
    private resultID: number | undefined;

    constructor(options: CustomReporterOptions) {
        this.options = options;
        console.log(`Custom reporter - Custom options received`);
        this.environmentName = config.ENV;
        this.postgresActions = new PostgresActions(config.postgresAPIUrl);
    }


    async initialize(): Promise<void> {
        if (!this.commonReporterUtils) {
            throw new Error('CommonReporterUtils not initialized. Call onBegin first.');
        }
        const { areaId, domainId, teamId, projectId } = await this.commonReporterUtils.getOrCreateIds();
        this.areaId = areaId;
        this.domainId = domainId;
        this.teamId = teamId;
        this.projectId = projectId;
    }

    async onBegin(fullConfig: FullConfig, suite: Suite) {
        console.log(`Custom reporter - Starting the run with ${suite.allTests().length} tests`);
        this.commonReporterUtils = new CommonReporterUtils(this.options, this.environmentName, config.postgresAPIUrl);
        await this.initialize();
    }

    async onTestEnd(testCase: TestCase, result: TestResult): Promise<void> {
        try {
            if (this.projectId) {
                const isRetry = this.previousTestCaseId === testCase.id;
                const suiteName = path.basename(testCase.parent?.title, '.ts');
                // testCaseId: To read from test case tags/annotation
                // testCycleName: process.env.JIRA_CYCLE_NAME || '',
                // releaseVersion: process.env.VERSION_NAME || '',
                this.resultID = await this.postgresActions.createOrUpdateTestResults(
                    {
                        suiteName: suiteName,
                        testcaseName: testCase.title,
                        status: result.status,
                        executionTime: result.startTime,
                        executionDuration: result.duration,
                        envName: this.environmentName,
                        projectId: this.projectId,
                    },
                    isRetry,
                    this.resultID
                );
                console.log('Custom reporter: - Test result created:', this.resultID);
                this.previousTestCaseId = testCase.id;
            } else {
                console.error('Custom reporter - Project ID is not available');
            }
        } catch (error) {
            console.error('Custom reporter - Error creating test result:', error);
        }
    }
}

export default GrafanaPlaywrightReporter;
```

## Exhaustive Reporter Differences

There is exactly one difference:

```diff
- import { config } from './config';
+ import { config } from '../../utils/configurationDetails';
```

This is an intentional and necessary import-path adaptation for the survey-mod e2e folder structure.

No other differences were found in:

- Whitespace or blank lines
- Comments
- Variable names
- Property declarations
- Class name
- Method names
- Method order
- Logic order
- Error messages
- Logging
- Promise handling
- Retry handling
- Postgres calls
- Export behavior

## Method Verification

The following methods are behaviorally and line-by-line identical:

### Constructor

Both versions:

1. Store `options` in `this.options`.
2. Log `Custom reporter - Custom options received`.
3. Read `config.ENV` into `this.environmentName`.
4. Create `PostgresActions` with `config.postgresAPIUrl`.

### `initialize()`

Both versions:

1. Check whether `commonReporterUtils` is initialized.
2. Throw `CommonReporterUtils not initialized. Call onBegin first.` when it is not initialized.
3. Call `getOrCreateIds()`.
4. Assign `areaId`, `domainId`, `teamId`, and `projectId` in the same order.

### `onBegin()`

Both versions:

1. Log the number of tests from `suite.allTests().length`.
2. Create `CommonReporterUtils` with `this.options`, `this.environmentName`, and `config.postgresAPIUrl`.
3. Await `this.initialize()`.

### `onTestEnd()`

Both versions:

1. Enter the same `try/catch` block.
2. Check `this.projectId`.
3. Determine retries using `this.previousTestCaseId === testCase.id`.
4. Derive the suite name with `path.basename(testCase.parent?.title, '.ts')`.
5. Build the same result payload.
6. Call `createOrUpdateTestResults()` with the same arguments.
7. Log the created result ID.
8. Store `testCase.id` as `previousTestCaseId`.
9. Log the same missing-project message when no project ID exists.
10. Log the same error message if result creation throws.

The unused `fullConfig` parameter is also identical in both implementations.

## Automation `config.ts` Review

The complete automation config was reviewed. The Grafana-relevant values are:

```ts
ENV: process.env.ENV || 'DEV',

// Grafana Playwright Reporter configuration
postgresAPIUrl: process.env.POSTGRES_API_URL || 'https://postgres-api.qa.in.gfk.com/report-postgres/api/v1',
```

The rest of the automation `config.ts` defines:

- Project metadata
- Test timeout and assertion timeout
- Parallel execution settings
- Browser and viewport settings
- Browser launch options
- Locale and dataset values
- Storage state and logging
- Environment base URLs
- Share-mail configuration
- Jira configuration
- Report paths

None of those additional values are read by `grafana-reporter.ts`.

Our equivalent values are:

```ts
export const postgresAPIUrl =
  process.env.SM_POSTGRES_API_URL || 'https://postgres-api.qa.in.gfk.com/report-postgres/api/v1';

export const config = {
  ENV: process.env.ENV || 'DEV',
  postgresAPIUrl,
};
```

The `ENV` fallback is equivalent. The API variable name differs intentionally because the requested integration specifies `SM_POSTGRES_API_URL`; the fallback URL is identical.

### Line-by-Line Structural Findings

The conditional structure genuinely matches:

1. Both use `process.env.CI ? CI reporters : non-CI reporters`.
2. Both put `list` first in the CI branch.
3. Both include the Allure reporter after the existing general reporter.
4. Both conditionally add the LambdaTest reporter using the same `isLambdaTest` expression.
5. Both add Grafana only to the CI branch.
6. Both place Grafana after the LambdaTest reporter.
7. Both pass `areaName`, `domainName`, `teamName`, and `projectName`.

Differences between the configurations are intentional or formatting-only:

1. The automation CI branch uses JSON output; ours uses the existing HTML reporter. Preserving HTML was explicitly required.
2. The automation non-CI branch omits HTML; ours retains HTML because it was already present and was required to remain unchanged.
3. Reporter paths differ because the repositories have different folder structures.
4. The automation uses `AREA_NAME`, `DOMAIN_NAME`, `TEAM_NAME`, and `PROJECT_NAME`; ours uses the explicitly requested `SM_AREA_NAME`, `SM_DOMAIN_NAME`, `SM_TEAM_NAME`, and `SM_PROJECT_NAME`.
5. The fallback values differ intentionally. Ours uses `FMCG`, `DISCOVER`, `SURVEY MOD`, and `SURVEY-MOD-AUTOMATION`.
6. Our options include trailing commas; the source does not. This is formatting only.

## Final Conclusion

The reporter implementation is a faithful behavioral and line-by-line match to the automation repository. The only reporter-file discrepancy is the required config import path. The surrounding Playwright configuration intentionally differs to preserve this project’s existing HTML reporter behavior and to use the requested `SM_*` environment variables and fallback values.
