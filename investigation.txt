## ⚠️ Critical defect found (outside the 4 requested checks)

While reading `survey-builder.spec.ts` to answer Check 1, a broken test
block was found. `TC_BS_05` is never closed before `TC_BS_06`'s
`test.fixme(...)` begins, and the `addRatingQuestion()` call is missing
entirely:

```ts
  test('TC_BS_05: Add a Rating question', { tag: '@RatingQuestion' }, async () => {
    const surveyBuilderPage = new SurveyBuilderPage(basePage);

    await surveyBuilderPage.clickAddQuestion();
  test.fixme(
    'TC_BS_06: Add a Text question',
    { tag: '@TextQuestion' },
    async () => {
      // BLOCKED: no confirmed locator for the "Text" question type exists yet
      ...
    }
  );

  test('TC_BS_07: Add an NPS question', { tag: '@NPSQuestion' }, async () => {
    ...
```

There is no `});` closing `TC_BS_05` before `test.fixme('TC_BS_06'...)` and
every test after it (`TC_BS_07`, `TC_BS_08`, `TC_BS_09`, `TC_BS_14`,
`TC_BS_16`, and the describe block's own closing `});`) are all nested
**inside** `TC_BS_05`'s async callback. `test(...)`/`test.fixme(...)` calls
are plain function calls, so this is not a TypeScript type error (`npx tsc
--noEmit` will not catch it) — it is a structural/runtime defect. Playwright
requires `test()` to be registered during the synchronous top-level
execution of the file/describe block, not from inside another test's async
body, so at runtime this will either throw ("Test can only be defined in a
test.describe or a test file") or silently fail to register `TC_BS_06`
through `TC_BS_16` as their own tests.

This is a regression, not a pattern difference from `start-from-scratch.spec.ts`
(which has no such issue). Flagged here because it directly affects Check 1's
file and must be fixed before the file is usable, but per your instructions
no fix has been applied.

## Check 3 — Page object structure (`surveyBuilder.page.ts`)

**Result: PARTIAL PASS** — class shape matches, but most methods skip the
try/catch error-wrapping convention used throughout `start-from-scratch.page.ts`.

Matches the reference:
```ts
// surveyBuilder.page.ts
export class SurveyBuilderPage extends CommonPage {
  constructor(basePage: BasePage) {
    super(basePage);
    this.resourceManager.registerResources(
      SURVEY_BUILDER_PAGE_COMPONENT_NAME,
      surveyBuilderPageResources
    );
  }
```
```ts
// start-from-scratch.page.ts
export class StartFromScratchPage extends CommonPage {
  constructor(basePage: BasePage) {
    super(basePage);
    this.resourceManager.registerResources(
      START_FROM_SCRATCH_PAGE_COMPONENT_NAME,
      startFromScratchPageResources
    );
  }
```
Both extend `CommonPage`, take `BasePage` in the constructor, call
`super(basePage)`, and register resources the same way. Both use
`this.webActionHandler.getWebElement(this.resourceManager.getResource(...))`
consistently for every element lookup.

Reference convention — every action method wraps its body in try/catch with
the standard message format:
```ts
// start-from-scratch.page.ts
async clickStartFromScratch(): Promise<void> {
  try {
    const startFromScratch = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('startFromScratch', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    await startFromScratch.waitFor(SMALL_TIMEOUT);
    await startFromScratch.click();
  } catch (error) {
    throw new Error(`Failed to click Start from scratch: ${error instanceof Error ? error.message : error}`);
  }
}
```

Methods in `surveyBuilder.page.ts` that do **not** follow this — no
try/catch at all, so a failed `waitFor`/`click` throws a raw Playwright
error instead of a `Failed to ...` message:

- `clickQuestionTypeResource` (private helper)
- `fillQuestionText` (private helper)
- `fillLabeledField` (private helper)
- `addOptionToQuestion`
- `addRowToQuestion`
- `addColumnToQuestion`
- `toggleRequired`
- `clickAddQuestion`
- `openReviewMode`
- `selectQuestionForReview`
- `deleteSelectedQuestions`
- `exitReviewMode`
- `saveDraft`
- `publishSurvey`

Example (no try/catch):
```ts
async clickAddQuestion(): Promise<void> {
  const addQuestion = this.webActionHandler.getWebElement(
    this.resourceManager.getResource('addQuestionLink', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
  );
  await addQuestion.waitFor();
  await addQuestion.click();
  await this.webActionHandler.delay(PANEL_TRANSITION_DELAY);
}
```

Methods that **do** follow the convention correctly: `addSingleChoiceQuestion`,
`addMultipleChoiceQuestion`, `addRatingQuestion`, `addNPSQuestion`,
`addPointScaleQuestion`, `addMultiScaleQuestion`, `setSurveyTitle` — all
wrap their bodies in try/catch with the
`Failed to ...: ${error instanceof Error ? error.message : error}` format,
matching the reference exactly.

## Check 4 — Locator JSON shape and naming convention

**Result: PARTIAL PASS** — JSON shape matches; file/element naming
convention does not.

Shape comparison — both use the same top-level shape:
```json
// surveyBuilder.json
{
 "name": "Survey Builder Page",
 "webElements": [
 { "elementName": "questionTypeSingleChoice", "selectorType": "css", "selectorValue": "[data-test-id='question-type-SINGLE_CHOICE']" },
 ...
 ]
}
```
```json
// start-from-scratch.locator.json
{
  "name": "Survey Generation Page",
  "webElements": [
    { "elementName": "startFromScratch", "selectorType": "text", "selectorValue": "Start from scratch" },
    ...
  ]
}
```
Both have `"name"` + `"webElements"` array of `{ elementName, selectorType,
selectorValue }` objects. No structural/shape deviation.

Deviations found:
1. **File name convention** — every other locator file in
   `e2e/locators/survey/` uses kebab-case with a `.locator.json` suffix:
   `start-from-scratch.locator.json`, `start-with-prompt.locator.json`,
   `select-panelist.locator.json`, `login.locator.json`. The survey builder
   file is named `surveyBuilder.json` — camelCase, and missing the
   `.locator` suffix. Same inconsistency on the page-object side:
   `surveyBuilder.page.ts` vs. the kebab-case `start-from-scratch.page.ts` /
   `start-with-prompt.page.ts`.
2. Indentation in `surveyBuilder.json` uses 1-space nesting for the
   `webElements` array entries instead of the 2-space/4-space indentation
   used in `start-from-scratch.locator.json` (cosmetic only, not a
   functional issue).
