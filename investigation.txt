Fix for the Jfrog related issue
Hello General,
As some of you may already know, the ADLM Support team was unable to resolve the issues with the existing JFrog Artifactory. Therefore, a new JFrog Artifactory instance has been deployed:
https://nielseniq.jfrog.io/
Ilian Ninov helped us publish the following items to the new Artifactory:
GTA image for test execution through the pipeline
GTA library
Azure Login library
To get your test project working again, please complete the following steps:
Sign in to the Artifactory using the Azure AD button on the login screen:
https://nielseniq.jfrog.io/
Click your profile icon and select Edit Profile.
Generate a new Identity Token.
Copy the token and store it securely. Do not share it with anyone or commit it to your repository.
On your laptop, create a new environment variable with the following details:
Name: JFROG_RO_TOKEN
Value: Your newly generated identity token
Remove the existing content from your project’s .npmrc file and replace it with the following:
@gfk:registry=https://nielseniq.jfrog.io/artifactory/api/npm/mi-data-platform-npm-local/
//nielseniq.jfrog.io/artifactory/api/npm/mi-data-platform-npm-local/:_authToken=${JFROG_RO_TOKEN}
registry=https://nielseniq.jfrog.io/artifactory/api/npm/npmjs-remote/
//nielseniq.jfrog.io/artifactory/api/npm/npmjs-remote/:_authToken=${JFROG_RO_TOKEN}
Delete the existing node_modules folder.
Ensure that your package.json uses the latest versions of GTA and Azure Login:
"@gfk/azure-login": "latest",
"@gfk/gta": "latest"
Run the following command:
npm install --verbose
Verify that the installation completes without any errors.
PS: To fix your failing pipeline due to the old artifactory token in it, please contact your team's SRE to get the token or credentials required for the new jfrog artifactory and get it updated in the CI CD variables.
