Fix 1 — default language not English
Already implemented, unchanged — global-setup.ts already switches unconditionally for any LOCALE, including en-US:


console.log(`Switching user language to ${envConfig.LOCALE}...`);
await new ProfilePage(basePage).setUserLocale(envConfig.LOCALE);
// The auth state was saved at login, before the language switch; refresh it so tests reuse the switched session.
await basePage.getWebActions().getStorageState('storage/auth.json');
console.log(`User language set to ${envConfig.LOCALE}.`);

It never skips based on LOCALE === DEFAULT_LOCALE, so it already attempts a switch for en-US runs too.

What was actually broken was the skip/switch decision inside setUserLocale (profile.page.ts): it decided "already in locale" via isAppInLocale(), which reads the Launchpad greeting heading (e.g. "Welcome," for en-US, "Bienvenue," for fr-FR) — a hardcoded natural-language word, undefined for every other locale (so it never skipped for them). I replaced that with reading the current language directly off the Profile/Account settings element (getLocaleLabel(), which navigates to Account settings and reads profileLanguageInput's text) and comparing it to the expected label for the requested locale — pure element state, no English-word heuristics, and it works for every LOCALE uniformly.
