## 1. `addPointScaleQuestion()` — exact current code

From [page-objects/survey/surveyBuilder.page.ts](page-objects/survey/surveyBuilder.page.ts):

```ts
  /**
   * TC_BS_08 — Point Scale. Shares the exact same `survey-scale-editor` Angular
   * component (and matrix-actions hover mechanism) as Multi Scale — confirmed
   * via source, see class-level comment #11.
   */
  async addPointScaleQuestion(
    questionIndex: number,
    questionText: string,
    rows: string[],
    columns: string[]
  ): Promise<void> {
    try {
      await this.clickQuestionTypeResource('questionTypePointScale');
      await this.fillQuestionText(questionIndex, questionText);
      for (let i = 0; i < rows.length; i++) {
        if (i >= 2) {
          await this.addRowToQuestion();
        }
        await this.fillLabeledField(`Row ${i + 1}`, rows[i]);
      }
      for (let i = 0; i < columns.length; i++) {
        if (i >= 2) {
          await this.addColumnToQuestion();
        }
        await this.fillLabeledField(`Column ${i + 1}`, columns[i]);
      }
      await this.clickAddQuestion(); // finalizes/saves this question, see class-level comment #9 for the double-click risk this introduces
    } catch (error) {
      throw new Error(`Failed to add Point Scale question: ${error instanceof Error ? error.message : error}`);
    }
  }
```

## 5. Last run's actual error / trace

Found an existing result folder for this exact test:
`test-results/survey-survey-builder-Surv-48bec--Add-a-Point-Scale-question-chromium/`
(`error-context.md`, `test-failed-1.png`, `trace.zip`).

### Exact error

```
Test timeout of 300000ms exceeded.
```

**No other thrown error or exception message is present.** This is Playwright's global per-test
timeout (confirmed in `playwright.config.ts`: `timeout: 300 * 1000`), not a specific
"element not found" / "locator resolved to N elements" error. The `use:` block in
`playwright.config.ts` sets no explicit `actionTimeout`, so individual actions (e.g. `.fill()`)
have no per-action timeout ceiling of their own and will keep auto-retrying until the whole test
is killed at 300s — consistent with "the test completes a long run with no specific error, rather
than failing fast," matching the reported symptom of nothing getting filled.

### Page snapshot / screenshot at time of failure — important, unexpected finding

The accessibility snapshot and the attached `test-failed-1.png` screenshot (viewed directly) show
**only 5 questions on the page** at the moment of timeout:

1. "How satisfied are you with this product?" (Single Choice) — correct, matches test data.
2. "Which features do you use regularly?" (Multiple Choice) — correct, matches test data.
3. "Rate your experience" (Rating, star icons) — correct, matches test data.
4. "How likely are you to recommend this product to a colleague?" (NPS, 1-10 scale) — correct,
   matches test data.
5. **"cvbvcb"** — a Point-Scale-style radio-button matrix question, already collapsed/saved, with
   row labels "bbmnbn", ".mn,n", "kj,j,kjkl" and column labels "mnmn,mn,", "mn,mn,m".

**This 5th question does not match any test data configured in `dev-test-data.json`** (neither
`multiScale`'s "Rate the following aspects of the product" / "Ease of use" etc., nor
`pointScale`'s same values). The text content ("cvbvcb", "mnmn,mn,", "bbmnbn", etc.) looks like
manual/ad-hoc typed input rather than automation-generated content — **this looks like a
pre-existing, already-saved question left over from a previous manual testing session against the
same persisted "Automation Test Survey"**, not something created by this test run. There is no
"Multi Scale" question visible anywhere in this snapshot, despite `TC_BS_09` (Multi Scale) being a
real, implemented test today.

**Not independently confirmed:**

## Summary of findings (no fix applied)

- Code and test-data wiring for `TC_BS_08` all look internally consistent (index 6, correct test
  data shape, no `test.fixme()`).
- The failure is a full 300s test-timeout with no specific thrown error — consistent with an
  action (most likely the question-text fill) retrying indefinitely against a locator that never
  resolves, given this repo's `webActions`/`playwright.config.ts` have no shorter per-action
  timeout to fail fast instead.
- The live page at time of failure had a 5th question ("cvbvcb"...) that doesn't correspond to any
  configured automated test data — most likely leftover from a prior manual session on the same
  persisted survey, and its presence/position could be shifting what `questionIndex` actually
  resolves to in the live DOM for the question this test is trying to create.
