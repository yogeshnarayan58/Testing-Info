### 1. `proceedToNextAfterDatasetSelection()` — `applyButton` vs `nextButton`

**File:** [e2e/page-objects/survey/start-from-scratch.page.ts](page-objects/survey/start-from-scratch.page.ts#L133-L142)

Current code:
```typescript
async proceedToNextAfterDatasetSelection(): Promise<void> {
  try {
    const nextButton = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('applyButton', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    await nextButton.waitFor(SMALL_TIMEOUT);
    await nextButton.click();
  } catch (error) {
    throw new Error(`Failed to click Next after dataset selection: ${error instanceof Error ? error.message : error}`);
  }
}
```

**Status:** ✅ ALREADY FIXED (confirmed correct as-is). Earlier in this session, live DOM
inspection confirmed `applyButton` and `nextButton` resource entries resolve to the same
`data-test-id` (`apply-dataset-btn`), so using `'applyButton'` here is functionally correct
and no reviewer-requested change is needed. Only the local variable name (`nextButton`) is
misleading, not the resource key — not a functional bug.

```typescript
    const chooseDatasetBreadcrumb = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('chooseDatasetBreadcrumb', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)

    const isOnDatasetScreen = await chooseDatasetBreadcrumb.isVisible();
    if (!isOnDatasetScreen) {

      return hasReachedDataviewScreen;
    }
    ...
```

**Status:** ✅ ALREADY FIXED. The code no longer does a bare `return true` when
`chooseDatasetBreadcrumb` isn't visible. Instead it now positively verifies progress by
checking for the `chooseDataviewBreadcrumb` (next screen) and returns that real visibility
result (`hasReachedDataviewScreen`). This is the "real fix" (checking for the next screen),
not the rejected one-line `return true` → `return false` swap.
