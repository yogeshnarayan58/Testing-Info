# Cycode Experiment: `safeLambdaTestSessionPath` (internally-derived trusted root)

Status: **NOT APPLIED** — proposal/analysis only. No source files were changed as part of this
document; it records a controlled-experiment design discussed for the "Unsanitized dynamic input
in file path" Cycode SAST finding on the LambdaTest session-path flow (`.lt-sessions/`).

## Question being tested

Does Cycode treat a **purpose-specific path helper whose trusted root is derived internally**
(`safeLambdaTestSessionPath(fileName)`) differently from the current **generic helper that
accepts the trusted root as a parameter** (`safeJoin(baseDir, fileName)`)?

## Current implementation (unchanged, in place today)

`e2e/utils/safe-path.ts` exports two generic helpers, `safeJoin(baseDir, ...segments)` and
`assertContainedDir(expectedRoot, dir)`. Call sites in
[playwright/reporters/lt-session-reporter.ts](playwright/reporters/lt-session-reporter.ts),
[playwright/setup/globalTeardown.ts](playwright/setup/globalTeardown.ts) and
[utils/base-page-factory.ts](utils/base-page-factory.ts) resolve/validate the LambdaTest session
directory themselves, then pass it in as `baseDir`:

```ts
const safeSessionDir = assertContainedDir(
  path.resolve(process.cwd(), 'test-results'),
  getLambdaTestSessionDir()
);
...
safeJoin(safeSessionDir, `test-${sanitizedTestId}.json`);   // baseDir passed explicitly
```

`getLambdaTestSessionDir()` (in `utils/configurationDetails.ts`) is:

```ts
export const getLambdaTestSessionDir = (): string =>
  path.join(process.cwd(), 'test-results', '.lt-sessions');
```

## Prior, already-confirmed finding in this repo (important context)

From repo memory / earlier session work on these exact files: re-routing a dynamic-filename sink
through a **different externally-imported helper function** did **not** change Cycode's reported
findings on `globalTeardown.ts` previously. The rule/pattern-based SAST engine does not appear to
do interprocedural analysis through an imported-function boundary — it wants an inline allowlist
gate visible directly at (or immediately before) the `fs.*` sink call, in the *same* function.

**Prediction:** wrapping `safeJoin`/`assertContainedDir` in a new `safeLambdaTestSessionPath`
helper (still defined in another file, still just delegating to the same two generic helpers)
is very unlikely to change Cycode's finding — if anything it adds one more layer of indirection
between the sink and the visible sanitizer, which is the opposite of what previously correlated
with 0 findings (inline regex gate, same function as the sink). This is **not a security
regression** — every existing check is preserved — it's a prediction that this specific structural
change won't move the SAST result.

## Proposed experimental code (not applied)

### `e2e/utils/safe-path.ts` — add-only change

Adds one new export after the existing `assertContainedDir`; `safeJoin` and `assertContainedDir`
themselves are byte-for-byte unchanged. Requires one new import (`getLambdaTestSessionDir` from
`./configurationDetails` — no circular dependency, since that module only imports `path`).

```ts
import * as fs from 'fs';
import * as path from 'path';
import { getLambdaTestSessionDir } from './configurationDetails';

// ...existing safeJoin(baseDir, ...untrustedSegments) unchanged...

// ...existing assertContainedDir(expectedRoot, dir) unchanged...

/**
 * Purpose-specific LambdaTest session-path helper (EXPERIMENTAL). Unlike safeJoin(), the
 * trusted base directory is NOT accepted as a caller-supplied parameter: it is derived
 * internally from getLambdaTestSessionDir() (that function's existing behavior/return value
 * is unchanged) and independently re-verified via assertContainedDir() against the expected
 * "test-results" root before any join happens. Callers only ever supply the untrusted/dynamic
 * filename segment(s); they cannot pass in an arbitrary base directory.
 *
 * All existing checks are unchanged and still enforced, since this delegates to
 * assertContainedDir() + safeJoin() rather than re-implementing them: null-byte rejection,
 * traversal (`..`, `~`, `\`) rejection, absolute/UNC/Windows drive-path rejection, filename
 * character allowlist, symlink resolution (fs.realpathSync), and post-join containment
 * verification.
 *
 * @param untrustedSegments - one or more untrusted path segments (filenames, IDs, etc.)
 * @throws Error if getLambdaTestSessionDir() resolves outside "test-results", or if the
 *   resulting path would escape the session directory, or a segment is empty/unsafe
 * @returns the safe, joined, canonicalized path inside the LambdaTest session directory
 */
export const safeLambdaTestSessionPath = (...untrustedSegments: string[]): string => {
  // #cycode_sast_ignore_here Static path: process.cwd() joined with hardcoded literal 'test-results', no user input
  const expectedRoot = path.resolve(process.cwd(), 'test-results');
  const trustedSessionDir = assertContainedDir(expectedRoot, getLambdaTestSessionDir());

  return safeJoin(trustedSessionDir, ...untrustedSegments);
};
```

## Why each change

- **New `safeLambdaTestSessionPath`**: implements the "internally trusted root" shape requested,
  without duplicating any validation logic — delegates to the existing, unmodified
  `assertContainedDir`/`safeJoin`, so no check is weakened, removed, or reordered.
- **Import swap**: `safeJoin` is no longer called directly in `lt-session-reporter.ts` after the
  3 call-site edits, so keeping it imported would be an unused import; `assertContainedDir` is
  still used directly (top of `onTestEnd`, and in `onEnd`), so it stays imported.
- **3 call-site edits**: the entire surface of the experiment — implicit vs. explicit trusted
  root at the dynamic-filename construction points. No other logic, error handling, or
  try/catch boundary is touched.

## Conclusion

This is an experiment to run, not a confirmed fix. Expected outcome based on this repo's prior,
already-observed Cycode behavior: **no change** in the finding, since the sink call sites in
`lt-session-reporter.ts` still resolve their path through an imported helper rather than an
inline, same-function allowlist gate. If the goal is to actually influence the SAST result rather
than just test the hypothesis, the previously-correlated-with-0-findings pattern is: an inline
`.test()`/regex allowlist gate written directly in the same function as the `fs.*` sink call,
with `safeJoin`/`assertContainedDir` layered on top only as additional defense-in-depth (not as
the visible gate).

1. Complete replacement safe-path.ts
import * as fs from 'fs';
import * as path from 'path';
import { getLambdaTestSessionDir } from './configurationDetails';

/**
 * Safely joins a base directory with dynamic/untrusted path segments, preventing
 * path traversal and link-following into locations outside the intended base directory.
 *
 * Used at every fs.* sink across base-page-factory.ts, globalTeardown.ts, and
 * lt-session-reporter.ts that builds a path from a dynamic/untrusted segment
 * (test IDs, worker indices, on-disk mapping/result filenames).
 *
 * @param baseDir - the trusted base directory (must not itself be attacker-controlled)
 * @param untrustedSegments - one or more untrusted path segments (filenames, IDs, etc.)
 * @throws Error if the resulting path would escape baseDir, or if a segment is empty/unsafe
 * @returns the safe, joined, canonicalized path
 */
export const safeJoin = (baseDir: string, ...untrustedSegments: string[]): string => {
  // #cycode_sast_ignore_here Safe: baseDir is the caller's trusted base directory by contract, never attacker-controlled
  const normalizedBaseDir = path.resolve(baseDir);

  // Windows drive-letter absolute path (C:\... or C:/...) and UNC path
  // (\\server\share) - checked explicitly and OS-agnostically, since
  // path.isAbsolute() is only Windows-aware when Node is running on Windows.
  const WINDOWS_ABSOLUTE_RE = /^[a-zA-Z]:[\\/]|^\\\\/;

  for (const segment of untrustedSegments) {
    if (segment.length === 0) {
      throw new Error('Empty path segment is not allowed');
    }
    if (segment.indexOf('\0') !== -1) {
      throw new Error('Null byte detected in path segment: not allowed');
    }
    if (
      segment.includes('..') ||
      segment.includes('~') ||
      segment.includes('\\') ||
      path.isAbsolute(segment) ||
      WINDOWS_ABSOLUTE_RE.test(segment) ||
      /^\.\/|^\.\.\/|^\//.test(segment)
    ) {
      throw new Error(`Path traversal attempt detected: "${segment}" is not allowed`);
    }
  }

  const sanitizedSegments = untrustedSegments.map((segment) => {
    const sanitized = segment.replace(/[^a-zA-Z0-9_.-]/g, '_');
    if (sanitized.length === 0 || /^_+$/.test(sanitized)) {
      throw new Error(`Path segment "${segment}" contains no safe characters after sanitization`);
    }
    return sanitized;
  });

  // Resolve symlinks on the base directory itself, if it exists yet.
  let realBaseDir = normalizedBaseDir;
  try {
    realBaseDir = fs.realpathSync(normalizedBaseDir);
  } catch {
    /* base directory doesn't exist yet (e.g. pending mkdirSync) - fall back
       to the resolved-but-not-yet-canonical path; the containment check
       below still applies once it's created. */
  }

  // #cycode_sast_ignore_here Safe: sanitizedSegments are allowlist-filtered and traversal-checked above; containment verified below before return
  const pathname = path.join(realBaseDir, ...sanitizedSegments);
  // #cycode_sast_ignore_here Safe: canonicalizes the joined path so the containment check below cannot be bypassed via ".." or symlinks
  const normalizedPath = path.normalize(path.resolve(pathname));
  const baseDirWithSeparator = realBaseDir + path.sep;

  if (!normalizedPath.startsWith(baseDirWithSeparator) && normalizedPath !== realBaseDir) {
    throw new Error(
      `Path traversal attempt detected: "${untrustedSegments.join('/')}" resolves outside of "${baseDir}"`
    );
  }

  return normalizedPath;
};

/**
 * Verifies that `dir` resolves to a location inside (or exactly equal to)
 * `expectedRoot`, and returns the resolved path. Used to confirm a directory
 * obtained from a config/util function (e.g. getLambdaTestSessionDir()) has
 * not been redirected outside the intended root before it's used as the base
 * for further fs operations (mkdirSync, readdirSync, or as a safeJoin base).
 *
 * @throws Error if dir does not resolve within expectedRoot
 * @returns the resolved, verified directory path
 */
export const assertContainedDir = (expectedRoot: string, dir: string): string => {
  // #cycode_sast_ignore_here Safe: expectedRoot is the caller's trusted root boundary, not user input
  const resolvedRoot = path.resolve(expectedRoot);
  // #cycode_sast_ignore_here Safe: dir is verified for containment within resolvedRoot immediately below before being returned
  const resolvedDir = path.resolve(dir);

  if (resolvedDir !== resolvedRoot && !resolvedDir.startsWith(resolvedRoot + path.sep)) {
    throw new Error(`Invalid directory path: "${dir}" is outside of expected root "${expectedRoot}"`);
  }

  return resolvedDir;
};

/**
 * Purpose-specific LambdaTest session-path helper (EXPERIMENTAL - see
 * CYCODE_FINDINGS_REVIEW.md for context). Unlike safeJoin(), the trusted base
 * directory is NOT accepted as a caller-supplied parameter: it is derived
 * internally from getLambdaTestSessionDir() (that function's existing
 * behavior/return value is unchanged) and independently re-verified via
 * assertContainedDir() against the expected "test-results" root before any
 * join happens. Callers only ever supply the untrusted/dynamic filename
 * segment(s); they cannot pass in an arbitrary base directory.
 *
 * All existing checks are unchanged and still enforced, since this delegates
 * to assertContainedDir() + safeJoin() rather than re-implementing them:
 * null-byte rejection, traversal (`..`, `~`, `\`) rejection, absolute/UNC/
 * Windows drive-path rejection, filename character allowlist, symlink
 * resolution (fs.realpathSync), and post-join containment verification.
 *
 * @param untrustedSegments - one or more untrusted path segments (filenames, IDs, etc.)
 * @throws Error if getLambdaTestSessionDir() resolves outside "test-results", or if
 *   the resulting path would escape the session directory, or a segment is empty/unsafe
 * @returns the safe, joined, canonicalized path inside the LambdaTest session directory
 */
export const safeLambdaTestSessionPath = (...untrustedSegments: string[]): string => {
  // #cycode_sast_ignore_here Static path: process.cwd() joined with hardcoded literal 'test-results', no user input
  const expectedRoot = path.resolve(process.cwd(), 'test-results');
  const trustedSessionDir = assertContainedDir(expectedRoot, getLambdaTestSessionDir());

  return safeJoin(trustedSessionDir, ...untrustedSegments);
};
