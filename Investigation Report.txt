## PART 1 — Dataset selection

### 1. `searchAndSelectDataset()` — original implementation (before this change), start-from-scratch.page.ts

```typescript
async searchAndSelectDataset(searchTerm: string, datasetLabel: string, _datasetIndex: number): Promise<void> {
  try {
    // Check-before-click: no locator exists for "a dataset tile is already selected" —
    // the closest confirmed signal is whether the "Choose a dataset" screen is still
    // showing at all. If it's gone, a dataset must already be selected — skip search.
    const chooseDatasetBreadcrumb = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('chooseDatasetBreadcrumb', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    const isOnDatasetScreen = await chooseDatasetBreadcrumb.isVisible();
    if (!isOnDatasetScreen) {
      console.log('↷ "Choose a dataset" screen not shown — assuming already selected, skipping search');
      return;
    }

    // Check-before-search: the 'defaultDataset' element (confirmed "default-dataset-selected"
    // class) reflects whatever dataset was previously chosen. It may not exist at all if
    // nothing was ever selected — that's treated as "not matched", not an error.
    const defaultDatasetElement = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('defaultDataset', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    const defaultDatasetText = await defaultDatasetElement.getText().catch(() => '');
    const isDefaultDatasetAlreadySelected = defaultDatasetText.trim().toLowerCase().includes(datasetLabel.trim().toLowerCase());
    if (isDefaultDatasetAlreadySelected) {
      console.log(`↷ Dataset "${datasetLabel}" already selected as default — skipping search`);
      return;
    }

    // Check-before-search: if the desired dataset tile is already visible on the
    // unfiltered list, skip the search-toggle/search-input steps entirely and click it.
    const existingDatasetElement = this.webActionHandler.getWebElement(
      this.resourceManager.getDynamicResource('datasetByLabel', datasetLabel, START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    const isDatasetAlreadyVisible = await existingDatasetElement.isVisible().catch(() => false);
    if (isDatasetAlreadyVisible) {
      console.log(`↷ Dataset "${datasetLabel}" already visible — skipping search, clicking directly`);
      await existingDatasetElement.click();
      return;
    }

    const searchToggle = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('searchToggle', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    await searchToggle.waitFor(SMALL_TIMEOUT);
    await searchToggle.click();

    const searchInput = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('searchInput', START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    await searchInput.waitFor(SMALL_TIMEOUT);
    await searchInput.enterText(searchTerm);
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);

    const datasetElement = this.webActionHandler.getWebElement(
      this.resourceManager.getDynamicResource('datasetByLabel', datasetLabel, START_FROM_SCRATCH_PAGE_COMPONENT_NAME)
    );
    await datasetElement.waitFor(SMALL_TIMEOUT);
    await datasetElement.click();
  } catch (error) {
    throw new Error(`Failed to search and select dataset "${datasetLabel}": ${error instanceof Error ? error.message : error}`);
  }
}
```

### 2. `panelist-flow.helper.ts` — target pattern (full file)

```typescript
import { BasePage } from '@gfk/gta';
import { SelectPanelistPage } from './select-panelist.page';

type DimensionSelectionsArg = Parameters<SelectPanelistPage['setDimensionSelections']>[0];

export async function completePanelistSelectionFlow(
  basePage: BasePage,
  dimensionSelections: DimensionSelectionsArg
): Promise<boolean> {
  const selectPanelistPage = new SelectPanelistPage(basePage);
  await selectPanelistPage.setDimensionSelections(dimensionSelections);
  await selectPanelistPage.clickSearchForPanelists();
  await selectPanelistPage.click250Responses();
  await selectPanelistPage.clickProceedToSurveyBuilder();
  return selectPanelistPage.isBuildSurveyPageLoaded();
}
```

### What `searchAndSelectDataset()` originally did, step by step

1. Reads `chooseDatasetBreadcrumb` — if the "Choose a dataset" screen isn't showing at all, **returns silently** (`void`), assuming a prior selection already happened.
2. Reads `defaultDataset` text — if it already matches `datasetLabel`, **returns silently**.
3. Checks if the target dataset tile (`datasetByLabel`) is already visible unfiltered — if so, clicks it and **returns silently**.
4. Otherwise, clicks `searchToggle` → types into `searchInput` → waits → clicks the resolved `datasetByLabel` element.
5. Any thrown error along the way is caught and re-thrown as a new `Error` with a `Failed to search and select dataset "<label>"` message.
6. Return type was `Promise<void>` in every branch — there was no way for the caller to distinguish "already selected, skipped" from "searched and selected" from "did nothing because it detected an unexpected state." The caller then had to make a **second, separate call** to `isDatasetSelectionConfirmed()` to get any boolean signal at all.

### Gap vs. `panelist-flow.helper.ts`'s shape (as originally assessed)

`completePanelistSelectionFlow()` is a standalone exported function that chains several void-returning page-object action calls and ends by calling one boolean-returning verification method (`isBuildSurveyPageLoaded()`), returning that boolean directly to the caller — the caller then asserts on it. `searchAndSelectDataset()` didn't match that shape: it returned `void` in every branch and required the spec to call a second method (`isDatasetSelectionConfirmed()`) afterward to get a boolean. See PART B below for the change made to close this gap.

## PART 2 — Navigate / base URL

### 1. `CommonPage` — original file (before this change), `e2e/page-objects/common/common-page.ts`

```typescript
/**
 * Common base page object for this project's page objects.
 *
 * Mirrors Omni Shopper's CommonTestCase (src/lib/common/pages/common-test-case/common-test-case.ts):
 * initializes webActionHandler/resourceManager from BasePage in the constructor and exposes a
 * single shared navigateToUrl() implementation, so page objects no longer need to duplicate the
 * try/catch/navigateTo navigation logic.
 */
import { BasePage, WebActions } from '@gfk/gta';
import { ResourceManager } from '../../utils/resource-manager';
import { NAVIGATION_TIMEOUT } from '../../constants/timeout-constants';

export class CommonPage {
  protected webActionHandler: WebActions;
  protected resourceManager: ResourceManager;

  constructor(protected basePage: BasePage) {
    this.webActionHandler = basePage.getWebActions();
    this.resourceManager = new ResourceManager({});
  }

  public async navigateToUrl(targetUrl: string, timeout: number = NAVIGATION_TIMEOUT): Promise<void> {
    try {
      await this.webActionHandler.navigateTo(targetUrl, timeout, 'domcontentloaded');
    } catch (navigationError) {
      console.error(`Navigation to URL failed: ${targetUrl}`, navigationError);
      throw navigationError;
    }
  }
}
```

### 3. Omnishopper's pattern for comparison

`config.ts` — single source of the base URL via a getter (`get BASE_URL()`), consumed everywhere as `config.BASE_URL`. `CommonTestCase.navigateToUrl()` is the shared navigation method (~30 classes extend it), with `navigateToReportUrl()` layered on top for retry/wait logic. The documented exception is `FormatPanel`, which doesn't extend `CommonTestCase` and calls `webActionHandler.navigateTo()` directly.

### 4. Original assessment

The navigation *method* (`navigateToUrl`) was already an equivalent, verbatim mirror of omnishopper's `CommonTestCase.navigateToUrl()`. The base URL *resolution* was not equivalent — omnishopper has one `config.BASE_URL` source; this repo had the same fallback literal and the same join logic duplicated across multiple files. **Partially there** — the navigation method matched, the base-URL sourcing didn't.

## PART A — Implemented: single BASE_URL source + shared URL-join helper

### What changed

1. **New file** [e2e/config/env.config.ts](env.config.ts) — the single shared source for the base URL, mirroring omnishopper's `config.BASE_URL` getter:
   ```typescript
   export const DEFAULT_BASE_URL = 'https://si.connect.nielseniq.io/reportexperience-dev';

   export const envConfig = {
     get BASE_URL(): string {
       return process.env.BASE_URL || DEFAULT_BASE_URL;
     },
   };
   ```
   It's implemented as a **getter** (not a plain constant computed at import time) so it still reads the correct value regardless of when `dotenv.config()` ran relative to this module being imported — the env var is only read at the moment `.BASE_URL` is accessed, not at module-load time.

2. **[playwright.config.ts](playwright.config.ts)** — replaced its own `process.env.BASE_URL || '...'` line with `const baseURL = envConfig.BASE_URL;`. Trailing-slash normalization for Playwright's `use.baseURL` option stays local to this file (it's the one place that needs a *normalized-with-trailing-slash* value for Playwright's own config, not a joined page URL).

3. **[helpers/global-setup.ts](helpers/global-setup.ts)** — replaced its own `process.env.BASE_URL || '...'` line with `const baseURL = envConfig.BASE_URL;`.

4. **[page-objects/common/common-page.ts](page-objects/common/common-page.ts)** — added a new `buildUrl(baseURL, relativePath)` method alongside `navigateToUrl()`, extracting the `endsWith('/') + new URL(path, base)` join logic that was previously copy-pasted in 3 files:
   ```typescript
   public buildUrl(baseURL: string, relativePath: string): string {
     const normalizedBaseURL = baseURL.endsWith('/') ? baseURL : `${baseURL}/`;
     return new URL(relativePath, normalizedBaseURL).toString();
   }
   ```
   Because it's on `CommonPage`, every subclass (`StartFromScratchPage`, `StartWithPromptPage`, `LoginPage`, etc.) inherits it automatically — no re-import needed to use it, only to supply a base URL.

5. **[page-objects/survey/start-from-scratch.page.ts](page-objects/survey/start-from-scratch.page.ts)** and **[page-objects/survey/start-with-prompt.page.ts](page-objects/survey/start-with-prompt.page.ts)** — `navigateToSurvey()` in both files now reads:
   ```typescript
   async navigateToSurvey(): Promise<void> {
     const surveyURL = this.buildUrl(envConfig.BASE_URL, 'survey');
     await this.navigateToUrl(surveyURL);
   }
   ```
   replacing their own 3-line fallback-literal + normalize + `new URL(...)` block. Both files now import `envConfig` from `../../config/env.config`.

6. **[page-objects/common/login.page.ts](page-objects/common/login.page.ts)** — `login()` still takes `baseURL` as a parameter (it does not read `process.env.BASE_URL` itself, that responsibility stays with the caller in `global-setup.ts`, which now sources it from `envConfig`), but the internal join logic was replaced with:
   ```typescript
   const surveyURL = this.buildUrl(baseURL, 'survey');
   ```

### Where the single source now lives

`envConfig.BASE_URL` in `e2e/config/env.config.ts` is the **only** place the fallback literal `'https://si.connect.nielseniq.io/reportexperience-dev'` appears. `playwright.config.ts`, `global-setup.ts`, `start-from-scratch.page.ts`, and `start-with-prompt.page.ts` all consume it from there instead of re-declaring it.

The URL-join logic (`endsWith('/')` + `new URL(path, base)`) now lives **only** in `CommonPage.buildUrl()`. `login.page.ts`, `start-from-scratch.page.ts`, and `start-with-prompt.page.ts` all call `this.buildUrl(...)` instead of re-implementing it.

## PART B — Implemented: `searchAndSelectDataset()` returns `Promise<boolean>`

### What changed

**[page-objects/survey/start-from-scratch.page.ts](page-objects/survey/start-from-scratch.page.ts)** — `searchAndSelectDataset()`'s return type changed from `Promise<void>` to `Promise<boolean>`. Every branch that previously ended with a bare `return;` (or fell through to the end of the function) now ends with `return this.isDatasetSelectionConfirmed();` instead:

- Branch 1 — "Choose a dataset" screen not shown at all (assumed already selected): now `return this.isDatasetSelectionConfirmed();` instead of `return;`.
- Branch 2 — default dataset text already matches `datasetLabel`: now `return this.isDatasetSelectionConfirmed();` instead of `return;`.
- Branch 3 — target dataset tile already visible unfiltered, clicked directly: now `return this.isDatasetSelectionConfirmed();` instead of `return;`.
- Branch 4 — normal search-toggle → search-input → click flow: now ends with `return this.isDatasetSelectionConfirmed();` instead of falling off the end of the `try` block with an implicit `void`.

The existing `isDatasetSelectionConfirmed()` method itself was **not removed** — it's now called internally by `searchAndSelectDataset()` from all four branches instead of being called separately by the spec.

**[tests/survey/start-from-scratch.spec.ts](tests/survey/start-from-scratch.spec.ts)** — the `'Dataset Selection'` test now assigns and asserts on `searchAndSelectDataset()`'s own return value directly, removing the second `isDatasetSelectionConfirmed()` call:
```typescript
const isDatasetSelectionConfirmed = await surveyPage.searchAndSelectDataset(
  datasetConfig.searchTerm,
  String(DATASET_NAME),
  datasetConfig.datasetIndex
);

assertTrue(
  isDatasetSelectionConfirmed,
  `Expected "Choose a dataset" confirmation not visible after selecting ${DATASET_NAME}`
);
```

### Known caveat (flagged, not silently "fixed")

Branch 1 fires precisely when `chooseDatasetBreadcrumb.isVisible()` is `false` (the "Choose a dataset" screen is not showing at all). Immediately returning `this.isDatasetSelectionConfirmed()` — which itself waits for and checks the same `chooseDatasetBreadcrumb` locator — will, in the common case, evaluate that locator again and find it still not visible, yielding `false`. That is the literal, mechanical result of folding the confirmation check into every branch as requested; it is not something this change silently overrode with a hardcoded `true` for that branch. This is a pre-existing ambiguity in the original code (already called out in that branch's own comment: *"no locator exists for 'a dataset tile is already selected'"*) surfacing more visibly now that the branch's outcome feeds directly into the caller's assertion instead of being invisible behind a `void` return. No fix for this ambiguity was applied — only the literal boolean-fold requested.
