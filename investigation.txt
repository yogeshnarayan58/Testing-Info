## Notes / decisions

- Tooltip overlays (#6, #14): `niq-tooltip` supports an `niqTooltipDataTestId` input (renders `<id>-content` in the overlay). That is a different attribute from `data-test-id`, so I did not add it. Decide whether to allow it.
- #7: `rephrase-send-loading-${i}` cannot be added as a second `data-test-id` on the same element; making the ID conditional would change the existing `rephrase-send-${i}`. Locator can keep using `.rephrase-send-loading` or `rephrase-send-${i}` + class.
- #54: `niq-dialog` builds `${id}-title`, so the host ID is `publish-survey-dialog` to avoid colliding with the `publish-dialog-title` ID on the title div.
- #15 etc.: `niq-toggle` renders its checkbox as `${host data-test-id}-input-checkbox` (verified in `@nielseniq/athena-core`), so the Required toggle now resolves to `required-toggle-${questionNumber}-input-checkbox`.
- Editors: text-editor's question text field has no `question-text-input-*` ID (only Rating was requested).
- `question-option-*` inner inputs render as `…-input`, which matches `[data-test-id$='-input']` used by `survey-builder.page.ts:1385`; first match is still the question text field (earlier in DOM), but the locator should move to the exact ID.
- Save/Discard (#8, #9) are static IDs per the doc; scope with the question row / `inline-add-editor`.
- `select-question-${i}-icon` is already emitted by `niq-checkbox`; the locator may already be correct.
