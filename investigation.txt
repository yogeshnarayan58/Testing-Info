## Section D — how data-test-id lands: HOST vs INNER element

Evidence is from this repo's templates and e2e locator patterns only; niq-* component internals (node_modules) were not inspected.

| component | evidence | landing |
|---|---|---|
| `niq-button` | `data-test-id="publish-survey"` / `data-test-id="save-draft"` / `data-test-id="generate-questions"` etc. written as a plain or `[attr.]` attribute directly on the `<niq-button>` tag, and e2e locators that use these ids (`publishSurveyButton`, `saveDraftButton`, `generateQuestionsButton`) match the **exact same string with no suffix** | HOST element |
| `niq-icon-button` | `[attr.data-test-id]="'rephrase-send-' + i"` written directly on `<niq-icon-button>` (preview-mode.component.html:48); no e2e locator independently exercises a `-${suffix}`-mangled id for this component in this repo | HOST element (same attribute-binding pattern as niq-button; not independently confirmed by a suffix-mismatch case the way niq-text-field/niq-checkbox/niq-toggle were) |
| `niq-text-field` | Template binds `[attr.data-test-id]="'question-text-input-' + questionNumber()"` on the `<niq-text-field>` host (choice/nps/scale editors), but the e2e locator `questionTextInput` must match `[data-test-id='question-text-input-${text}-input']` — an extra **`-input` suffix** not written in any template | INNER element (component re-renders/forwards the given id onto an internal `<input>`, appending `-input`) — confirmed only via the e2e locator's required suffix, not by inspecting the component itself |
| `niq-toggle` | No template anywhere in the 5 question editors currently binds a `data-test-id` to `<niq-toggle>`, yet the stale `requiredToggle` locator expects `[data-test-id='-input-checkbox']` (empty prefix + `-input-checkbox` suffix) | UNKNOWN — the `-input-checkbox` suffix pattern suggests INNER landing with a compound suffix, but with no current template binding to confirm against, this cannot be verified from this repo's evidence alone |
| `niq-checkbox` | Template binds `[attr.data-test-id]="'select-question-' + $index"` on `<niq-checkbox>` host (review-mode.component.html:8), but `selectQuestionByIndex` needs a `-icon` suffix while `selectQuestionCheckboxContainer` uses the base id unchanged as an ancestor selector | Mixed evidence: base id usable as ancestor (suggests it also stays on/near HOST), but a `-icon`-suffixed variant is expected elsewhere — most consistent with INNER landing on a nested icon element, with the id also still present/queryable on the HOST as an ancestor. Not fully resolved — reported as evidence-based inference, not a confirmed fact. |
