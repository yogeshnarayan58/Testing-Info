## Why `questionNumber()` instead of a static id

[Phase 6 investigation](data-test-id-phase6-nps-scale-fields.md) found that
`<survey-question-editor>` (and, in turn, `choice-editor` /
`nps-editor` / `scale-editor`) is instantiated **once per question**, inside
the `@for (q of questions(); ...)` loop in `preview-mode.component.html`.
Multiple question cards render simultaneously on the Build Survey screen, and
it's the common case (not an edge case) to have **more than one question of
the same type** on screen at once (e.g. two Single Choice questions). A
static id — whether shared across all three editors or suffixed per type
(`-nps`, `-scale`) — would still produce duplicate `data-test-id`s as soon as
two questions of the same type are both mounted.

`questionNumber()` is already available as an input signal on all three
editors (used in each template for the visible `{{ questionNumber() }}.`
label), is unique per question, and requires no new plumbing — so
`[attr.data-test-id]="'question-text-input-' + questionNumber()"` was used in
all three files instead of a static `data-test-id`.
