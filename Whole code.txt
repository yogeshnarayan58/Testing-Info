## LambdaTest Integration

### Summary

**What it does / why it's needed**
LambdaTest is a cloud browser grid. Instead of launching a local Chromium instance, Playwright
connects over a WebSocket (`chromium.connect(wsEndpoint)`) to a remote browser hosted by
LambdaTest, so tests can run on real remote OS/browser combinations (e.g. Windows 11 Chrome,
macOS Edge) and produce recorded video/network/console artifacts for each session. This is
controlled entirely by an `isLambdaTest = process.env.LAMBDATEST === 'true'` flag — when unset/false,
everything falls back to a normal local Chromium run.
(Source: [playwright.config.ts](file:///c:/Users/Yogesh.Upadhyay/Downloads/disc-fe-omnishopper-ui-automation/playwright.config.ts) — `const isLambdaTest = process.env.LAMBDATEST === 'true';`;
[base-page-factory.ts](file:///c:/Users/Yogesh.Upadhyay/Downloads/disc-fe-omnishopper-ui-automation/src/lib/common/utils/base-page-factory.ts) — same flag and `chromium.connect(wsEndpoint)` call.)

**Files it touches** (confirmed by opening each one):
1. `playwright.config.ts` (repo root) — reads LT env vars, builds the `wsEndpoint` capability string, conditionally adds a `lambdatest-chromium` project, conditionally adds the `lt-session-reporter` to the reporter list, and throws if `isLambdaTest` is true but credentials are missing.
2. `src/lib/common/utils/base-page-factory.ts` — `BasePageFactory.createBasePage()` branches on `isLambdaTest`; when true it builds its own `wsEndpoint`, connects via `chromium.connect`, creates context/page, and writes per-test session-tracking files into `.lt-sessions/`.
3. `src/lib/common/utils/configurationDetails.ts` — exports `getLambdaTestBuildName(ltBuild, buildIdentifier)`, a shared helper used by both `playwright.config.ts`, `base-page-factory.ts`, and `globalTeardown.ts` to build a consistent LambdaTest build name (e.g. `"Discover build (123)"`).
4. `src/lib/common/utils/global-setup.ts` — Playwright `globalSetup`; deletes old `storage/auth.json`, clears/creates the `.lt-sessions/` directory before each run, then calls `BasePageFactory.createBasePage(true)` to log in and produce a fresh `storage/auth.json`.
5. `src/lib/playwright/reporters/lt-session-reporter.ts` — a custom Playwright `Reporter` (`LTSessionReporter`) that only activates when `process.env.LAMBDATEST === "true"`; on `onTestEnd` it reads the per-test session file written by `base-page-factory.ts` from `.lt-sessions/` and records a `fullName -> sessionName` mapping, writing both individual mapping files and a combined `session-mappings.json` in `.lt-sessions/`.
6. `src/lib/playwright/setup/globalTeardown.ts` — Playwright `globalTeardown`; when `isLambdaTest` is true, reads the `.lt-sessions/` mapping files, injects an `LT_SESSION` parameter into each Allure `*-result.json`, calls the LambdaTest Automation API (`https://api.lambdatest.com/automation/api/v1/sessions?...`) to fetch session IDs/status, adds a `"LambdaTest Video"` link into each Allure result, PATCHes each session's pass/fail status back to LambdaTest, and finally writes `allure-results/environment.properties` with the build URL/name/ID.
7. `lambdatest.yml` (repo root) — a YAML config consumed by the **LambdaTest CLI/GitHub Action** (not by Playwright directly) that defines platforms (Windows 11 Chrome/Edge, macOS Edge), tunnel usage, build naming via `${LAMBDATEST_BUILD_NAME}` / `${DATE_TIME}` placeholders, and debugging options (`video`, `networkLogs`, `idleTimeout`).
8. `.env.example` (repo root) — documents all `LAMBDATEST_*` / `LT_*` variables consumers must set.
9. `package.json` (repo root) — `test:lambdatest` script (`cross-env LAMBDATEST=true npx playwright test`); no LambdaTest npm package/SDK dependency exists — the "integration" is just a raw CDP WebSocket URL, so there is no `@lambdatest/*` npm package in `devDependencies`/`dependencies`.
10. `.gitignore` (repo root) — ignores `.lt-sessions/` (the cross-process session-mapping directory created by `base-page-factory.ts` / read by `lt-session-reporter.ts` and `globalTeardown.ts`).

**Environment variables / credentials required** (all confirmed present in `.env.example`):
| Variable | Where the value comes from |
|---|---|
| `LAMBDATEST` | Feature flag you set yourself (`true`/`false`) — not a credential. |
| `LAMBDATEST_USERNAME` / `LT_USERNAME` | Your LambdaTest account username, from the LambdaTest dashboard (Profile → Account Settings). |
| `LAMBDATEST_ACCESS_KEY` / `LT_ACCESS_KEY` | Your LambdaTest account access key, from the same LambdaTest Account Settings page. |
| `LT_PROJECT` | Free-text project label shown in the LambdaTest dashboard; defaults to `'OMNI Discover'` if unset (`playwright.config.ts` / `base-page-factory.ts`). |
| `LT_BUILD` | Free-text build label; defaults to `'Discover build'` if unset. |
| `LT_BUILD_IDENTIFIER` (or `BUILD_NUMBER` / `GITHUB_RUN_NUMBER`) | Optional suffix appended to the build name via `getLambdaTestBuildName`; typically supplied by CI (e.g. GitHub Actions run number), not manually. |
| `LT_TUNNEL` | Used only by `lambdatest.yml` (`lambdaTestTunnel: true`) for the LambdaTest CLI, not read anywhere in the TypeScript code found. |
| `LT_VIDEO`, `LT_NETWORK`, `LT_CONSOLE` | Boolean toggles for whether LambdaTest records video/network/console logs for the session; user-chosen, not credentials. |
| `LT_OBSERVABILITY` | Present in `.env.example` but **not referenced anywhere** in `playwright.config.ts`, `base-page-factory.ts`, `configurationDetails.ts`, `global-setup.ts`, `lt-session-reporter.ts`, or `globalTeardown.ts` (confirmed via search) — appears unused by the code, only documented. |
| `LT_IDLE_TIMEOUT` | Numeric seconds before an idle LambdaTest session is killed; user-chosen, defaults to `300`. |
| `LT_WORKERS` | Playwright worker count when running on LambdaTest; user-chosen, defaults to `1`. |
| `LT_DOWNLOAD_VIDEOS` | Present in `.env.example` but **not referenced** in any of the TypeScript files read — same as `LT_OBSERVABILITY`, appears unused by code. |

**Code-only (safe to add now) vs. credential-gated:**
- Code-only / safe without any account: the `isLambdaTest` branching logic itself, the `getLambdaTestBuildName` helper, the `.lt-sessions/` bookkeeping in `base-page-factory.ts`/`lt-session-reporter.ts`, and the conditional reporter/project wiring in `playwright.config.ts` — none of this requires a real LambdaTest account to exist in the codebase or to pass a normal (non-LambdaTest) local run, since `isLambdaTest` stays `false` by default.
- Credential-gated: actually running with `LAMBDATEST=true` requires a valid `LAMBDATEST_USERNAME`/`LT_USERNAME` + `LAMBDATEST_ACCESS_KEY`/`LT_ACCESS_KEY` pair — `playwright.config.ts` explicitly throws `'LambdaTest credentials missing!...'` if `isLambdaTest` is true and either is missing. The `globalTeardown.ts` LambdaTest API calls (`api.lambdatest.com/automation/api/v1/sessions`) also require these same credentials and will just log a warning and skip if missing (`"Missing LambdaTest credentials. Skipping API calls."`).

**npm packages needed:** None specific to LambdaTest. There is **no** `@lambdatest/*` package anywhere in `package.json`'s `dependencies`/`devDependencies` — connectivity is done via a raw `chromium.connect(wsEndpoint)` WebSocket URL built by hand, so `@playwright/test` (already required for Allure/Playwright itself) is the only relevant package. (Confirmed by reading the full `package.json` — no such dependency line exists.)

**Setup steps beyond code:**
- Create/have a LambdaTest account and obtain the username + access key from the LambdaTest dashboard.
- Populate `.env` with `LAMBDATEST=true`, `LAMBDATEST_USERNAME`/`LT_USERNAME`, `LAMBDATEST_ACCESS_KEY`/`LT_ACCESS_KEY`.
- If using the LambdaTest tunnel for localhost/private URLs (`lambdaTestTunnel: true` in `lambdatest.yml`), the LambdaTest Tunnel binary/CLI must be installed and running separately — this repo's code does not install or launch a tunnel process itself (no tunnel-related code found in any of the files read).
- `lambdatest.yml` implies use of the LambdaTest **CLI/GitHub Action** for platform-matrix runs, which is a separate tool from the `npx playwright test` path — nothing in the repository (as read) invokes this YAML file automatically; it appears to be config for an external LambdaTest CLI/action invocation not present in `package.json` scripts.

**Can it be tested/verified locally without external credentials?**
Partially. The conditional code paths (`isLambdaTest` false branch, i.e. ordinary local Chromium runs) can be fully exercised without any LambdaTest account — this is the default behavior. However, actually exercising the LambdaTest branch (`LAMBDATEST=true`) — the WebSocket connection, session registration files, the reporter, and `globalTeardown.ts`'s API calls — is **credential-gated**: it requires a real `LAMBDATEST_USERNAME`/`LT_USERNAME` + `LAMBDATEST_ACCESS_KEY`/`LT_ACCESS_KEY`, and `playwright.config.ts` will throw immediately without them.

#### 2. `base-page-factory.ts` (complete, verbatim)

```typescript
import { BasePage } from '@gfk/gta';
import { chromium } from '@playwright/test';
import fs from 'fs';
import path from 'path';
import { config } from '../../playwright/config';
import { WebActions } from '@gfk/gta/dist/core/web/webActions';
import { getLambdaTestBuildName } from './configurationDetails';

// Store session names with timestamp as key (for reporter lookup)
export const sessionRegistry: Array<{ timestamp: number; sessionName: string; title?: string }> = [];

// Map to store session per worker - each worker runs tests sequentially
export const workerSessionMap = new Map<number, string>();

// Global current session tracker - stores the last created session
export let currentLTSession: string | null = null;

export class BasePageFactory {
  static async createBasePage(forceHeadless?: boolean): Promise<BasePage> {
    const isLambdaTest = process.env.LAMBDATEST === 'true';

    const ltUser = process.env.LAMBDATEST_USERNAME || process.env.LT_USERNAME;
    const ltAccessKey = process.env.LAMBDATEST_ACCESS_KEY || process.env.LT_ACCESS_KEY;
    const ltProject = process.env.LT_PROJECT || 'OMNI Discover';
    const ltBuildBase = process.env.LT_BUILD || 'Discover build';
    const ltBuildIdentifier =
      process.env.LT_BUILD_IDENTIFIER ||
      process.env.BUILD_NUMBER ||
      process.env.GITHUB_RUN_NUMBER ||
      undefined;
    const ltBuild = getLambdaTestBuildName(ltBuildBase, ltBuildIdentifier);

    const ltVideo = process.env.LT_VIDEO === 'false' ? false : true;
    const ltNetwork = process.env.LT_NETWORK === 'true';
    const ltConsole = process.env.LT_CONSOLE === 'true';

    let storageState: string | undefined;
    const authPath = path.resolve(process.cwd(), 'storage/auth.json');

    if (fs.existsSync(authPath)) {
      storageState = authPath;
      console.log('Auth state loaded from storage/auth.json');
    } else {
      console.log('No auth state found - login required');
    }
    if (isLambdaTest) {
      console.log('Connecting to LambdaTest cloud...');

      const timestamp = Date.now();
      const sessionName = `Test-${timestamp}`;

      const ltOptions: any = {
        platform: 'Windows 11',
        project: ltProject,
        build: ltBuild,
        name: sessionName,
        user: ltUser,
        accessKey: ltAccessKey,
        network: ltNetwork,
        video: ltVideo,
        console: ltConsole,
      };

      if (forceHeadless !== undefined) {
        ltOptions.headless = forceHeadless;
      }

      const wsEndpoint = `wss://cdp.lambdatest.com/playwright?capabilities=${encodeURIComponent(
        JSON.stringify({
          browserName: 'pw-chromium',
          browserVersion: 'latest',
          'LT:Options': ltOptions,
        })
      )}`;

      const browser = await chromium.connect(wsEndpoint);
      console.log(`Connected to LambdaTest (Session: ${sessionName})`);

      const contextOptions: any = {
        acceptDownloads: true,
        viewport: { width: 1920, height: 1080 },
      };

      if (storageState) {
        contextOptions.storageState = storageState;
      }

      const context = await browser.newContext(contextOptions);
      const page = await context.newPage();

      // Store session info for reporter/global-teardown
      try {
        const workerIndex = Number(process.env.TEST_WORKER_INDEX || 0);
        const testId =
          process.env.__CURRENT_TEST_ID__ || (global as any).__CURRENT_TEST_ID__ || null;

        const sessionDir = path.join(process.cwd(), '.lt-sessions');
        fs.mkdirSync(sessionDir, { recursive: true });

        // store in memory
        (page as any).__LT_SESSION_NAME__ = sessionName;
        sessionRegistry.push({ timestamp, sessionName });
        workerSessionMap.set(workerIndex, sessionName);
        currentLTSession = sessionName;

        // append sessions.jsonl (fallback)
        fs.appendFileSync(
          path.join(sessionDir, 'sessions.jsonl'),
          JSON.stringify({ sessionName, timestamp, workerIndex }) + '\n',
          'utf-8'
        );

        // PRIMARY (parallel safe): write per-test session file
        if (testId) {
          fs.writeFileSync(
            path.join(sessionDir, `test-${testId}.json`),
            JSON.stringify({ sessionName, timestamp, testId }),
            'utf-8'
          );
          console.log(`[LT Session] ✓ test-${testId}.json written`);
        } else {
          console.warn('[LT Session] ⚠ testId not available, using fallback sessions.jsonl');
        }

        // optional worker file
        fs.writeFileSync(
          path.join(sessionDir, `worker-${workerIndex}.json`),
          JSON.stringify({ sessionName, timestamp }),
          'utf-8'
        );

        console.log(`[LT Session] Registered session: ${sessionName} (worker: ${workerIndex})`);
      } catch (err) {
        console.warn('[LT Session] Could not store session info:', err);
      }

      // Inject into BasePage
      (BasePage as any).browser = browser;
      (BasePage as any).context = context;
      (BasePage as any).page = page;
      (BasePage as any).webActions = new WebActions(page, context);

      return new (BasePage as any)();
    }
    const browserName = config.browser ?? 'chromium';
    let browserOptions = config.browserOptions ?? {};

    if (forceHeadless !== undefined) {
      browserOptions = { ...browserOptions, headless: forceHeadless };
    }

    const contextOptions = {
      acceptDownloads: true,
      recordVideo: process.env.PWVIDEO ? { dir: 'screenshots' } : undefined,
      viewport: null,
      storageState,
    };

    return await BasePage.initializer(browserName, browserOptions, contextOptions);
  }
}
```

#### 2b. `configurationDetails.ts` (complete, verbatim — shared helper used by both LambdaTest and Jira/Allure code)

```typescript
import { parseBoolean, resolveEnvValue } from './env-utils';

const DEFAULT_SUITE_NAME = 'Omni Reports';
const JIRA_FLAG_KEY = 'JiraUpdateEnabled';
const JIRA_FLAG_ALIASES = [JIRA_FLAG_KEY, 'JIRA_UPDATE_ENABLED', 'UpdateJira', 'UPDATE_JIRA'];
const SUITE_NAME_KEY = 'SuiteName';

export const getJiraFlagvalue = (): string => {
  for (const key of JIRA_FLAG_ALIASES) {
    const value = resolveEnvValue(key);
    if (value !== undefined) {
      return value.trim();
    }
  }
  return 'false';
};

export const shouldUpdateJira = (): boolean => {
  return parseBoolean(getJiraFlagvalue(), false);
};

export const getSuiteName = (): string => {
  const value = resolveEnvValue(SUITE_NAME_KEY) ?? resolveEnvValue('PLAYWRIGHT_SUITE_NAME');
  if (value && value.trim().length > 0) {
    return value.trim();
  }
  return resolveEnvValue('npm_package_name') ?? DEFAULT_SUITE_NAME;
};

/**
 * Constructs the LambdaTest build name with optional build identifier suffix.
 * Used consistently across playwright.config.ts and globalTeardown.ts.
 * 
 * @param ltBuild - Base build name (e.g., "Discover build")
 * @param buildIdentifier - Optional identifier to append (e.g., GitHub run number)
 * @returns Formatted build name with identifier if provided
 */
export const getLambdaTestBuildName = (
  ltBuild: string,
  buildIdentifier?: string
): string => {
  return buildIdentifier ? `${ltBuild} (${buildIdentifier})` : ltBuild;
};
```

#### 2c. `global-setup.ts` (complete, verbatim — Playwright `globalSetup`, prepares `.lt-sessions/` and auth state)

```typescript
/**
 * @fileoverview Global setup for Playwright tests.
 * Handles authentication state management and login initialization.
 *
 * This module is executed before running tests to establish authentication
 * and prepare the testing environment.
 */
import fs from "fs";
import path from "path";
import { BasePageFactory } from "./base-page-factory";
import { LoginPage } from "../pages/login-page/login-page";
import { config } from "../../playwright/config";

// Define constants
const AUTH_FILE_PATH = "storage/auth.json";
const LT_SESSIONS_DIR = ".lt-sessions";

/**
 * Performs global setup operations before tests are run.
 * - Validates environment variables
 * - Cleans up previous authentication state
 * - Performs login to establish a new auth state
 */
async function globalSetup(): Promise<void> {
  try {
    console.log("Starting global setup...");

    // Delete existing auth state if it exists
    if (fs.existsSync(AUTH_FILE_PATH)) {
      fs.unlinkSync(AUTH_FILE_PATH);
      console.log("Old authentication state deleted.");
    }

    // Clean up LambdaTest session files from previous run
    if (fs.existsSync(LT_SESSIONS_DIR)) {
      const files = fs.readdirSync(LT_SESSIONS_DIR);
      files.forEach(file => {
        fs.unlinkSync(path.join(LT_SESSIONS_DIR, file));
      });
      console.log(`Cleared ${files.length} old LambdaTest session file(s).`);
    } else {
      // Create directory if it doesn't exist
      fs.mkdirSync(LT_SESSIONS_DIR, { recursive: true });
      console.log("Created .lt-sessions directory.");
    }
    
    // Perform login and create new auth state (force headless mode for login)
    console.log(`Logging in to ${config.BASE_URL} in headless mode...`);
    const basePage = await BasePageFactory.createBasePage(true);
    const loginPage = new LoginPage(basePage);
    await loginPage.login(config.BASE_URL);
    console.log("Authentication successful. New auth state created.");
  } catch (error) {
    console.error("Global setup failed:", error);

    // Rethrow with context to ensure the setup failure is clearly indicated
    if (error instanceof Error) {
      throw new Error(`Global setup failed: ${error.message}`);
    } else {
      throw new Error("Global setup failed with an unknown error");
    }
  }
}

export default globalSetup;
```

```typescript
 * NOTE: This reporter does NOT create sessions - it only captures session names created by 
 * BasePageFactory (which uses getLambdaTestBuildName for consistent build naming).
 * Stores test -> session mapping into individual per-test JSON files 
 * (.lt-sessions/test-<id>-<pid>-<timestamp>.json) to avoid concurrent write conflicts.
 */

import { Reporter, TestCase, TestResult, FullResult } from "@playwright/test/reporter";
import * as fs from "fs";
import * as path from "path";

class LTSessionReporter implements Reporter {
  private testSessions = new Map<string, string>(); // fullName -> sessionName

  onBegin() {
    if (process.env.LAMBDATEST !== "true") return;
    
    console.log("[LT Reporter] Initialized - capturing LambdaTest sessions...");
  }

  onTestBegin(test: TestCase) {
    if (process.env.LAMBDATEST !== "true") return;
    
    process.env.__CURRENT_TEST_ID__ = test.id;
    (global as any).__CURRENT_TEST_ID__ = test.id;

    console.log(`[LT Reporter] Test started: "${test.title}" (testId: ${test.id})`);
  }

  onTestEnd(test: TestCase, result: TestResult) {
    if (process.env.LAMBDATEST !== "true") return;

    const testId = test.id;
    const sessionDir = path.join(process.cwd(), ".lt-sessions");
    const testSessionFile = path.join(sessionDir, `test-${testId}.json`);

    let sessionName: string | null = null;

    try {
      // 1st priority: test-specific session file
      if (fs.existsSync(testSessionFile)) {
        const data = JSON.parse(fs.readFileSync(testSessionFile, "utf-8"));
        sessionName = data.sessionName;

        // cleanup
        try {
          fs.unlinkSync(testSessionFile);
        } catch {}
      }

      // fallback: sessions.jsonl
      if (!sessionName) {
        const sessionsLogFile = path.join(sessionDir, "sessions.jsonl");
        const workerIndex = result.parallelIndex ?? 0;
        const testStartTime = result.startTime?.getTime() || 0;

        if (fs.existsSync(sessionsLogFile)) {
          const lines = fs.readFileSync(sessionsLogFile, "utf-8").split("\n").filter(Boolean);

          let bestMatch: { sessionName: string; diff: number } | null = null;

          for (const line of lines) {
            try {
              const s = JSON.parse(line);
              if (s.workerIndex === workerIndex && s.timestamp && testStartTime) {
                const diff = Math.abs(s.timestamp - testStartTime);
                if (diff < 60000 && (!bestMatch || diff < bestMatch.diff)) {
                  bestMatch = { sessionName: s.sessionName, diff };
                }
              }
            } catch {}
          }

          if (bestMatch) sessionName = bestMatch.sessionName;
        }
      }
    } catch (err) {
      console.error("[LT Reporter] Error reading session:", err);
    }

    if (!sessionName) {
      console.warn(`[LT Reporter] No session found for "${test.title}" (testId: ${testId})`);
      return;
    }

    const fullName = test.titlePath().filter(Boolean).join(" › ");
    // Normalize > separator to › for consistent mapping with globalTeardown
    const normalizedFullName = fullName.replace(/\s*>\s*/g, ' › ');
    
    this.testSessions.set(normalizedFullName, sessionName);

    console.log(`[LT Reporter] Stored: "${normalizedFullName}" -> ${sessionName}`);

    // Write mapping per test/worker to avoid concurrent write conflicts
    try {
      fs.mkdirSync(sessionDir, { recursive: true });

      // Use a collision-resistant filename per test/process to prevent concurrent write conflicts
      const safeTestId = testId.replace(/[^a-zA-Z0-9-]/g, '_');
      const mappingFile = path.join(sessionDir, `test-${safeTestId}-${process.pid}-${Date.now()}.json`);
      fs.writeFileSync(
        mappingFile,
        JSON.stringify({
          testName: test.title,
          fullName: normalizedFullName,
          testId,
          sessionName,
          timestamp: Date.now(),
        }, null, 2),
        "utf-8"
      );

      console.log(`[LT Reporter] Mapping written to ${path.basename(mappingFile)}`);
    } catch (err) {
      console.error("[LT Reporter] Failed to write mapping:", err);
    }
  }

  onEnd(result: FullResult) {
    if (process.env.LAMBDATEST !== "true") return;

    if (this.testSessions.size === 0) {
      console.warn("[LT Reporter] No sessions captured.");
      return;
    }

    try {
      const sessionDir = path.join(process.cwd(), ".lt-sessions");
      fs.mkdirSync(sessionDir, { recursive: true });

      const mappingFile = path.join(sessionDir, "session-mappings.json");
      fs.writeFileSync(mappingFile, JSON.stringify(Object.fromEntries(this.testSessions), null, 2));

      console.log(`[LT Reporter] Saved ${this.testSessions.size} session mappings.`);
    } catch (err) {
      console.error("[LT Reporter] Failed to save mappings:", err);
    }
  }
}

export default LTSessionReporter;
```

## Allure Integration

### Summary

**What it does / why it's needed**
Allure is a test-reporting tool. Playwright is configured to emit Allure result JSON files via
the `allure-playwright` reporter plugin into an `allure-results/` folder; those raw results are
later compiled into a browsable HTML report using the `allure-commandline` CLI (`allure generate`
/ `allure open`). This is unconditional — unlike LambdaTest, the `allure-playwright` reporter entry
is present in **both** the CI and local reporter arrays in `playwright.config.ts`, so Allure results
are always produced regardless of `LAMBDATEST`.
(Source: [playwright.config.ts](file:///c:/Users/Yogesh.Upadhyay/Downloads/disc-fe-omnishopper-ui-automation/playwright.config.ts) — `['allure-playwright', { outputFolder: 'allure-results' }]` appears in both branches of the `reporter` ternary.)

**Files it touches** (confirmed by opening each one):
1. `playwright.config.ts` — registers `['allure-playwright', { outputFolder: 'allure-results' }]` in the `reporter` array (both CI and non-CI branches).
2. `package.json` — declares `allure-playwright` and `allure-commandline` as `devDependencies`, and defines the `allure`, `allure:generate`, `allure:open` npm scripts.
3. `src/lib/playwright/setup/globalTeardown.ts` — post-processes the Allure result files after every run: reads every `allure-results/*-result.json`, optionally injects LambdaTest session/video info (see LambdaTest section above), and always writes `allure-results/environment.properties` with `Execution.Mode` (and LambdaTest build info when applicable, gated inside the `if (isLambdaTest)` block).
4. `.gitignore` — ignores `allure-results/` and `allure-report/` (the raw results directory and the generated HTML report directory) so they aren't committed.
5. No dedicated Allure config file (`allure.config.js`, `.allurerc`, `categories.json`, environment.properties **template**) was found anywhere in the repository — confirmed via a workspace-wide regex search for `categories\.json|environment\.properties|allure\.config|\.allurerc|allureConfig`.
