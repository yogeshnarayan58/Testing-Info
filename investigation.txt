## Login → Direct URL Navigation Check — 2026-09-30

**Exact current code (Setup test, `survey-builder.spec.ts`):**
```ts
test('Setup: reach Build Survey page via Start from Scratch', { tag: '@SurveyBuilderSetup' }, async () => {
  basePage = await BasePageFactory.createBasePage();
  const startFromScratchPage = new StartFromScratchPage(basePage);
  await startFromScratchPage.navigateToUrl('select-panelist');

  const reachedBuildSurvey = await completePanelistSelectionFlow(basePage, datasetConfig.dimensionSelections);

  assertTrue(reachedBuildSurvey, 'Expected to land on Build Survey page after panelist selection flow');
});
```

**Result: PASS — already correct, no changes made.**

The test already does exactly what was required: `BasePageFactory.createBasePage()`
runs (login/session reuse), then the very next line calls
`startFromScratchPage.navigateToUrl('select-panelist')` — a direct URL
navigation with no home-page or launchpad step in between. This is then
followed by `completePanelistSelectionFlow()`, unchanged.

**Note on `start-from-scratch.spec.ts`:** that file does **not** use a
direct-to-select-panelist navigation. Its Setup test calls
`surveyPage.navigateToSurvey()`, which lands on the **survey home page**
first, then reaches Select Panelist only after several UI steps
(`clickStartFromScratch()` → `selectProductOffering()` →
`searchAndSelectDataset()` → `proceedToNextAfterDatasetSelection()` →
`applyEntireDataset()`). That is the opposite of what this task asked for
(home-page navigation, not direct URL), so it was not used as a reference
for this check — `survey-builder.spec.ts`'s existing
`navigateToUrl('select-panelist')` call is the correct (and only) direct-URL
pattern in the codebase for this purpose. No file changes were made.
