## A) App source

### A1. "Search for Panelists" button — `panelist-dataselector.component.html`
- Element: `<niq-button id="report-btn-run" data-cy="report-btn-run" class="primary-btn run-btn" ...>` (the niq-button HOST element).
- Selector: `#report-btn-run` (existing e2e locator `[id='report-btn-run']`). **Stable id** (hard-coded in template). No `data-test-id`; `data-cy` is also present.
- Rendering rule (`runButtonState`, default `'hidden'`):
  - `hidden` -> element is NOT in the DOM (`@if (!hasCompletedPanelistSearch() && runButtonState !== 'hidden')`). It is hidden before any selection is made and again after the search report completes (`reportCompleted$` -> `'hidden'`).
  - `disabled` -> set after every selection change (`updateDataSelections`, ts ~L382), after dataset change (~L252), or when the prompt-validation event says not `VALID` / no selections (~L146-152).
  - `default` (enabled) -> prompt validation `promptStatus === 'VALID'`.
  - `loading` -> after click.
- How DISABLED is shown (confirmed in app template):
  1. CSS class on the host: `report-btn-run-disabled` (`[ngClass]`).
  2. niq-button input `[state]="'disabled'"` -> niq-button `classes` getter = `${size} ${state} ${mode} ${variant}`, so a `disabled` class token lands on its inner element; `disabled` getter = `super.disabled || state() === 'disabled'`.
  - NOT confirmed (niq-button template is a huge inline string in athena-core): whether a native `disabled` attribute or `aria-disabled` is rendered on the inner `<button>`. Existing e2e code for other niq-buttons checks aria-disabled / `state` attr / class token / inner `.disabled` property (see `survey-builder.page.ts` getAddQuestionDisabledState / Publish). **Recommended assertion:** `#report-btn-run.report-btn-run-disabled` (stable, from our own template) and, for "enabled", `:not(.report-btn-run-disabled)`.
- Gotcha: because the host stays in the DOM while disabled, `isVisible()` is true for disabled AND enabled states.

### B3. Can `setDimensionSelection` be called for 4 of 5 filters only, then the 5th later?
**Yes.** 
- `setDimensionSelections(selections[])` is just a for-loop over `setDimensionSelection(...)`, each call is independent and ends by clicking Done (panel closes, `PANEL_TRANSITION_DELAY`). It holds no cross-call state, and there is no "all 5 required" check.
- `dev-test-data.json -> datasets[<name>].dimensionSelections` is an array of 5 entries (productNoDataPrompt, retailerNoDataPrompt, geographyNoDataPrompt, demographicNoDataPrompt, periodNoDataPrompt). Test can pass `selections.slice(0, 4)` first and later call `setDimensionSelection(...)` (or `setDimensionSelections([fifth])`) with the 5th entry's fields. Order is irrelevant to the code; the existing array order is product, retailer, geography, demographic, period.
- Check-before-click guard: each call first reads the current dimension value (via `FILLED_TILE_DIMENSION_LABELS` for all 5); if already matching it returns early, if a different value it removes then re-selects. So re-calling is idempotent.
- Caveats for the "disabled until all 5 set" test:
  - After the 1st selection the Search button appears in `disabled` state (not hidden); it becomes enabled only when prompt validation reports `VALID` (after the 5th). Before any selection it is not in the DOM, so `isSearchForPanelistsButtonVisible()` (which does `waitFor()`) will throw/timeout — don't use it for the "before" state.
  - Need new method(s) e.g. `isSearchForPanelistsEnabled()` using `#report-btn-run` class `report-btn-run-disabled` (+ optionally inner button disabled).
  - `setDimensionSelection` parameters are positional (dimensionTab, items, parentItems, requiresFilterIconClick, filterIconClickAfterParent, skipParentSearch); `DimensionSelection` interface is not exported, but `Parameters<SelectPanelistPage['setDimensionSelections']>[0]` works (used in panelist-flow.helper.ts).
  - The existing spec test "Should enable Search for Panelists after all 5 filters are set" only asserts visibility — it never proves enabled.
  - Period uses `skipParentSearch` / `filterIconClickAfterParent`; these are data-driven, no code change needed.
