## 4. Gap analysis — is anything else missing?

**Key finding: `lambdatest.yml` is not actually wired into anything in Omni Shopper's repo.**
It is a standalone declarative file with no code, script, or CI step that reads or invokes it.

- **CI/CD workflow invoking `lambdatest.yml` or a LambdaTest CLI?**
  Checked all 6 files in `disc-fe-omnishopper-ui-automation/.github/workflows/`
  ([manual-automation-test-run.yml](../../../Downloads/disc-fe-omnishopper-ui-automation/.github/workflows/manual-automation-test-run.yml),
  `scheduler-report-after-run-base-setup.yml`, `scheduler-report-after-run-batch-1/2/3.yml`,
  `scheduler-report-basic-test-cases.yml`). None reference `lambdatest.yml` or any
  `lambdatest`/`lt-cli` CLI binary. They set plain environment variables
  (`LAMBDATEST`, `LAMBDATEST_USERNAME`, `LAMBDATEST_ACCESS_KEY`, `LT_USERNAME`, `LT_ACCESS_KEY`,
  `LT_PROJECT`, `LT_BUILD`, `LT_BUILD_IDENTIFIER`, `LT_TUNNEL`, `LT_VIDEO`, `LT_NETWORK`) and
  then just run `npx playwright test` directly — no LambdaTest CLI step of any kind.

  Relevant excerpt (manual-automation-test-run.yml):
  ```bash
  if [ "${{ github.event.inputs.USE_LAMBDATEST }}" = "Yes" ] || [ "${{ github.event.inputs.USE_LAMBDATEST }}" = "true" ]; then
    echo "LAMBDATEST=true" >> $GITHUB_ENV
    echo "LAMBDATEST_USERNAME=${{ secrets.LAMBDATEST_USERNAME }}" >> $GITHUB_ENV
    echo "LAMBDATEST_ACCESS_KEY=${{ secrets.LAMBDATEST_ACCESS_KEY }}" >> $GITHUB_ENV
    echo "LT_USERNAME=${{ secrets.LAMBDATEST_USERNAME }}" >> $GITHUB_ENV
    echo "LT_ACCESS_KEY=${{ secrets.LAMBDATEST_ACCESS_KEY }}" >> $GITHUB_ENV
    echo "LT_PROJECT=OMNI Discover" >> $GITHUB_ENV
    echo "LT_BUILD=Discover build - Manual Run" >> $GITHUB_ENV
    echo "LT_BUILD_IDENTIFIER=${{ github.run_number }}" >> $GITHUB_ENV
    echo "LT_TUNNEL=true" >> $GITHUB_ENV
  ```
  There is no `lambdatest` CLI invocation anywhere in these workflows.

- **npm script invoking the LambdaTest CLI?**
  Omni Shopper's `package.json` has:
  ```json
  "test:lambdatest": "cross-env LAMBDATEST=true npx playwright test",
  ```
  This is plain Playwright (`npx playwright test`) with an env var flag — it does **not**
  call any `lambdatest`/`lt-cli`/`lambdatest-setup` binary. No such script exists.

- **LambdaTest CLI tool listed as a dependency?**
  Checked all of `dependencies` and `devDependencies` in Omni Shopper's `package.json`
  (`@gfk/gta`, `@playwright/test`, `@types/node`, `allure-commandline`, `allure-playwright`,
  `cross-env`, `dotenv`, `typescript`, `rxjs`, `tslib`). **No LambdaTest CLI package
  (e.g. `lambdatest-cypress-cli`, `@lambdatest/*`, `lambda-tunnel`) is present.**

- **How does Omni Shopper actually run on LambdaTest, then?**
  Entirely through `playwright.config.ts`, not `lambdatest.yml`. When `LAMBDATEST=true`,
  the config builds a `connectOptions.wsEndpoint` pointing at
  `wss://cdp.lambdatest.com/playwright?capabilities=...` and passes `LT:Options`
  (`platform`, `build`, `user`, `accessKey`, `project`, `network`, `video`, `console`,
  `idleTimeout`) directly from environment variables (`LT_USERNAME`, `LT_ACCESS_KEY`,
  `LT_PROJECT`, `LT_BUILD`, etc.) sourced from `.env`/CI secrets. `lambdatest.yml` is never
  `require`'d, `read`'d, or referenced by path anywhere in the codebase (confirmed via
  full-repo text search for `lambdatest.yml` — zero matches outside the file itself).

- **Does `disc-fe-omni-survey-mod` have any of the above already?**
  - `e2e/package.json` already has an equivalent script:
    `"test:lambdatest": "cross-env LAMBDATEST=true npx playwright test"` — same pattern as
    Omni Shopper, already present.
  - `e2e/.env` / `e2e/.env.example` already define `SM_LT_*` variables
    (`SM_LT_USERNAME`, `SM_LT_ACCESS_KEY`, `SM_LT_PROJECT`, `SM_LT_BUILD`, `SM_LT_TUNNEL`,
    `SM_LT_VIDEO`, `SM_LT_NETWORK`, `SM_LT_CONSOLE`, `SM_LT_IDLE_TIMEOUT`, `SM_LT_WORKERS`),
    matching the naming used in the 4 changes made to `lambdatest.yml`.
  - **Missing (same as Omni Shopper — i.e., not a gap unique to us):** no LambdaTest CLI
    dependency, and no CI/CD workflow file under `.github/workflows/` in this repo that
    invokes LambdaTest at all (this repo has no equivalent of Omni Shopper's
    `manual-automation-test-run.yml` / `scheduler-report-*.yml`).
  - Not yet verified in this pass: whether `e2e/playwright.config.ts` in this repo actually
    builds the `wss://cdp.lambdatest.com/playwright` `connectOptions` block the way Omni
    Shopper's does — that file was not part of this task's scope but would need the same
    wiring for `npm run test:lambdatest` to actually route to LambdaTest's cloud grid rather
    than just setting an inert env var.

## 5. Status — is `lambdatest.yml` usable as-is?

**No — in both repos, `lambdatest.yml` is currently an orphaned/unused config file.**

- It is not read by Playwright, not referenced by any npm script, and not invoked by any CI
  workflow in Omni Shopper (the repo it was copied from) or in this repo.
- The actual LambdaTest cloud execution mechanism in Omni Shopper lives entirely in
  `playwright.config.ts` (the `wss://cdp.lambdatest.com/playwright` WebSocket endpoint built
  from `LT_*`/`LAMBDATEST_*` env vars), not in `lambdatest.yml`.
- Copying `lambdatest.yml` into `e2e/` is safe and consistent with the request, but by itself
  it does **not** enable or change any LambdaTest behavior for `disc-fe-omni-survey-mod`.
  For `npm run test:lambdatest` in this repo to actually run on LambdaTest's cloud, the
  equivalent `connectOptions`/`wsEndpoint` wiring must exist in `e2e/playwright.config.ts`
  (this was outside the scope of this task and was not verified/changed here).
- No additional CLI installation is required to have the file present, but no CLI would
  ever consume it either — it appears to be leftover/reference documentation rather than an
  active part of either repo's test execution path.
