Investigation Findings
No files were modified. Root cause identified below.

1. What npm test actually runs
package.json's script is:
"test": "playwright test"

It's a direct pass-through with no wrapper, no cross-env, and no stripping of env vars. Any VAR=value set before npm test on the same command line is inherited by the playwright test child process normally (on POSIX-style shells). This script itself does not touch CI.

2. Exact current gating line in playwright.config.ts
Re-read fresh from disk — the reporter array is gated exactly like this in playwright.config.ts:
reporter: process.env.CI
    ? [ ... , ['./playwright/reporters/grafana-reporter.ts', { ... }] ]
    : [ ... ],
This is unchanged from what was implemented — confirmed correct.

3. Anything that could reset/override process.env.CI before reporters are evaluated
Checked playwright.config.ts and every file it imports (config/env.config.ts, utils/configurationDetails.ts, helpers/global-setup.ts):

dotenv.config({ path: path.resolve(__dirname, '.env') }) runs at the top of playwright.config.ts. By default, dotenv does not override variables already present in process.env.
More importantly, .env contains no CI key at all — so even if dotenv did override, there's nothing in .env that touches CI.
A workspace-wide search for process.env.CI = (assignment) returned no matches anywhere in e2e.
Conclusion: nothing in the config or its imports resets CI.

4. Early-exit conditions in grafana-reporter.ts
Re-read fresh from disk — grafana-reporter.ts:

The constructor has no guard at all — if the class is instantiated, "Custom reporter - Custom options received" always logs unconditionally.
onBegin() also has no guard — "Custom reporter - Starting the run with X tests" always logs unconditionally if onBegin is invoked by  Playwright.
The only conditional branch is inside onTestEnd(), gated on this.projectId (set by initialize() → commonReporterUtils.getOrCreateIds()). If projectId were falsy, you'd still see the first two logs, plus "Custom reporter - Project ID is not available" per test — none of which appeared either.
Since none of the three logs appeared (not even the constructor log, which has zero conditions), the reporter class was never instantiated at all. That rules out #4 as the cause and points squarely at registration/config evaluation.

5. Playwright config evaluation timing
Playwright loads playwright.config.ts once, synchronously, at process startup, before running any tests — the reporter array is a plain JS expression evaluated then. process.env.CI must already be set in the environment of the Node process running npx playwright test at that moment. Setting CI inline before the command on the same shell line (CI=true npm test) is timed correctly in bash — npm inherits and passes environment down to the playwright test child process, and that happens before playwright.config.ts is loaded. So timing itself is not the problem, provided the variable is actually named CI and actually reaches that process.

6. The real root cause
Your terminal history for the run in question shows:
Terminal: bash
Last Command: Cl=true npm test
That is not CI=true npm test — it's Cl=true npm test (a variable named Cl, not CI). This is an extremely easy typo/visual mix-up (capital "I" vs. lowercase "l"). In bash this is syntactically valid, so it ran silently: it exported an unused variable Cl=true to the npm test process while process.env.CI remained unset (falsy) for that run. With process.env.CI falsy, playwright.config.ts's reporter array took the non-CI branch, grafana-reporter.ts was never referenced or instantiated by Playwright, and none of its logs — including the unconditional constructor log — could ever fire. This fully explains the symptom.

Guaranteed command
cross-env is already a devDependency here, so use it to remove any shell-specific ambiguity (works identically in bash, PowerShell, and cmd) and to make the variable name unmistakable:
npx cross-env CI=true npm test
Run from inside e2e. As a quick sanity check beforehand, you can also run node -e "console.log(process.env.CI)" immediately after setting it the same way, to confirm the shell actually set CI (not a typo'd variable) before invoking Playwright.
