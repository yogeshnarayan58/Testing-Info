## 4. What does the `name` field actually do?

- `name` is purely a **label/identifier** for the project. Playwright uses it for:
  - Display in the CLI/HTML report (test titles are prefixed with it, e.g. `[chromium] › test.spec.ts`).
  - Filtering via `--project=<name>` on the CLI.
  - `test.info().project.name` at runtime.
  - Dependency references (`dependencies: ['setup']` etc. match against `name`).
- There is **no technical requirement** that `name` match a key in the `devices()` map. `devices['Desktop Chrome']` is just a plain JS object of preset `use` options (userAgent, viewport, browserName: 'chromium', etc.) shipped in `@playwright/test`. You could name a project `"foo"` and still spread `devices['Desktop Chrome']` into its `use` block, or name it `"chromium"` and use completely custom `launchOptions`/`viewport` with no `devices[]` reference at all (as Omni Shopper does).
- **Conclusion**: matching the `name` string to a `devices()` preset key is a **semantic/naming convention only** — not enforced or required by Playwright.

In our (`e2e/playwright.config.ts`) case, `name: 'chromium'` happens to align with the actual `devices['Desktop Chrome']` preset being spread, so the "mismatch" concern raised in the PR comment (that `name` doesn't literally equal `'Desktop Chrome'`) is **not a functional issue** — it's standard practice across Playwright configs (including Playwright's own default template) to name the project `chromium`/`firefox`/`webkit` while pointing at `devices['Desktop Chrome']`/`devices['Desktop Firefox']`/`devices['Desktop Safari']` respectively.

## 5. Adding a Microsoft Edge project

Playwright requires the `devices` import (already present in `e2e/playwright.config.ts`: `import { defineConfig, devices } from '@playwright/test';`) and a project entry using the `Desktop Edge` preset plus the `msedge` channel:

```typescript
{
  name: 'Microsoft Edge',
  use: { ...devices['Desktop Edge'], channel: 'msedge' },
},
```

### Omni Shopper Edge status

Their config does **not** have an active Edge (or Firefox/WebKit/mobile) project. The exact block:

Only the single active `chromium` project (with `launchOptions`/`viewport: null`) and the conditional `lambdatest-chromium` project actually run. None of these commented sections are active anywhere in their config.

## Summary for PR response

1. **"name and device not matching"**: Not a real bug — `name` is just a label with no functional link to `devices()` keys. `e2e/playwright.config.ts` already correctly spreads `devices['Desktop Chrome']` under a project named `chromium`, which is the standard convention.
2. **"can we add Microsoft Edge or any other browser?"**: Yes — add a project entry using `devices['Desktop Edge']` + `channel: 'msedge'` (shown above). Omni Shopper's repo has the same Edge/Firefox/WebKit snippets but all commented out/inactive — they are not currently running multi-browser either.
