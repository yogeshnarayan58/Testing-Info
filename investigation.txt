Save draft also calls a real endpoint (`/survey`, `saveSurveyDraft()` L170-171) — it is not a no-op either; only its *toast/list verification* is flagged `@WIP`.

## 2. Save draft logic

- **Enabled when:** NOT FOUND IN SOURCE — no `isSaveDraftDisable`/disabled binding found for the "Save draft" button in [survey-header.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-header/survey-header.component.html#L49) (only a `loading` vs `default` `[state]`, driven by `isSavingDraft()`/`isLoadingFolders()`); no question-count gate located (unlike Publish's `questions().length < 3`).
- **Save-a-copy dialog fields:** `SaveACopyComponent` bound at [survey-header.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-header/survey-header.component.html#L65-76): title field, `createNewFolder` option, `acceptText` = `folderDialogText.continue` ("Continue", `FOLDER_DIALOG_TEXT.continue` in [build-survey.ts](../libs/survey-mod-lib/src/lib/features/build-survey/models/build-survey.ts#L278)) when in publish action, else `folderDialogText.saveDraft` ("Save as draft"). E2E fills title via `saveCopyTitleInput`, picks `myAssetsTreeItem` ("My Assets" tree node), clicks `savePendingChangesButton` ([SurveyBuilder.page.ts](page-objects/survey/SurveyBuilder.page.ts#L570-589) `fillSaveCopyDialog`).
- **What Continue/confirm does:** `handleLocationSelection()` ([survey-header.component.ts](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-header/survey-header.component.ts#L113-123)) — for draft action calls `saveAsDraft(result)` (L126-...) which calls `updateSurveyFolder(result)` then `surveyService.saveSurveyDraft(SurveyStatusType.DRAFT, currentAssetIdValue)` → POST to `/survey` (`saveSurveyDraft` at [survey.service.ts](../libs/survey-mod-lib/src/lib/features/build-survey/services/survey.service.ts#L170-171), `submitSurvey` L186-204). Folder is taken from the selected tree node (`result.folder.assetId`), not hardcoded.
- **Feedback after saving:** Toast `InsertToast('success', 'Survey saved as draft successfully.', { dismissAfter: ToastTime.DISMISSAFTER, size: 'large', containerClass: 'survey-action-toast' })` — [survey-header.component.ts](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-header/survey-header.component.ts#L146). On error: `InsertToast('error', errorMessage, ...)` (L153). Note the e2e locator/assert text ("Success, survey saved as a draft successfully", [surveyBuilder.locator.json](locators/survey/surveyBuilder.locator.json#L44) and [survey-builder.spec.ts](tests/survey/survey-builder.spec.ts#L303)) does **not** literally match the component string ("Survey saved as draft successfully.") — NOT FOUND IN SOURCE where/if the toast UI prepends "Success, "; `ToastService`/`InsertToast` implementation is external (`@nielseniq/athena-core`), not in this repo.
- **Where the draft appears afterwards:** Component navigates to `['../build-survey', response.data.surveyId]` only if no `surveyId` route param yet ([survey-header.component.ts](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-header/survey-header.component.ts#L148-151) — truncated in read, continuation not fully re-read). E2E's `isSurveyVisibleInMyAssets()` navigates to `survey/my-assets` and checks a `savedAssetGridcellByTitle` role=gridcell ([SurveyBuilder.page.ts](page-objects/survey/SurveyBuilder.page.ts#L604-611)). A `my-assets` feature does exist ([my-assets-page.component.ts](../libs/survey-mod-lib/src/lib/features/my-assets/components/my-assets-page.component.ts)) but whether the saved-draft list/grid itself is implemented there: NOT FOUND IN SOURCE (not inspected further per scope; this is exactly what `TC_BS_SAVE_DRAFT`'s `@WIP` tag flags as pending).

## 3. Publish logic

- **Enabled/blocked rule:** `[isPublishDisable]="questions().length < 3"` — [build-survey.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/build-survey.component.html#L24). Footer renders `[state]="isPublishDisable() ? 'disabled' : 'active'"` on `data-test-id="publish-survey"` ([footer.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/footer/footer.component.html#L4-6)). Exact **max** is 10, `MAX_SURVEY_QUESTIONS = 10` ([build-survey.ts](../libs/survey-mod-lib/src/lib/features/build-survey/models/build-survey.ts#L110)), enforced on Add/Duplicate (`isAtMaxQuestions()`), with tooltip text "You have already reached the maximum number of questions." ([preview-mode.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/preview-mode/preview-mode.component.html#L67)). There is no separate "max 10 blocks Publish" code path found — Publish's own gate is only the `< 3` minimum; NOT FOUND IN SOURCE of an explicit max-question check inside the Publish button logic itself (10 is just the ceiling on total questions anyway).
- **What the user sees when blocked:** button `state="disabled"` (visual only); NOT FOUND IN SOURCE of a tooltip/message specifically on the disabled Publish button (unlike Add/Duplicate's tooltip).
- **Dialogs in order:** 1) click Publish (`publish-survey`) → 2) Save-a-copy dialog (title + My Assets + Continue) via `prepareForPublish()`/`loadAndOpenFolderDialog` ([survey-header.component.ts](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-header/survey-header.component.ts#L94-99)) → 3) "Confirm publish?" dialog (`survey-publish-popup.component.html`). Confirmed by e2e: `publishSurvey()` clicks Publish then fills the Save-a-copy dialog ([SurveyBuilder.page.ts](page-objects/survey/SurveyBuilder.page.ts#L693-706)), then `confirmPublish()` waits for `confirmPublishDialogText` ("Confirm publish?").
- **"Confirm publish?" content:** Title `PUBLISH_DIALOG_TEXT.title = 'Confirm publish?'` ([build-survey.ts](../libs/survey-mod-lib/src/lib/features/build-survey/models/build-survey.ts#L262)). Dimensions rendered via `<crf-data-summary id="publish-data-summary" ...>` ([survey-publish-popup.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-publish-popup/survey-publish-popup.component.html#L6-9)); e2e confirms each renders `data-test-id="ds-<Label>_Dimension"` inside `#publish-data-summary` (comment, [SurveyBuilder.page.ts](page-objects/survey/SurveyBuilder.page.ts#L709-711)). Response count: `<span class="publish-response-count">{{ selectedResponseCount | number }} {{ publishText.responses }}</span>` (L14 of same html), text "You chose to receive" + count + "responses." (`responseSummary`/`responses` in `PUBLISH_DIALOG_TEXT`).
- **Confirm/Cancel behavior:** Cancel button calls `close()` (just closes dialog, no API call) ([survey-publish-popup.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-publish-popup/survey-publish-popup.component.html#L24-26)). Confirm calls `confirmPublish()` ([survey-publish-popup.component.ts](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-publish-popup/survey-publish-popup.component.ts#L50-65)): closes dialog, sets `isPublishing=true` (drives a `role="status" aria-label="Publishing survey"` loader, [survey-publish-popup.component.html](../libs/survey-mod-lib/src/lib/features/build-survey/components/survey-publish-popup/survey-publish-popup.component.html#L36-38)), calls `surveyService.publishSurvey(PUBLISHED, currentAssetIdValue)`.
- **Success message:** `InsertToast('success', 'Survey published successfully.', { dismissAfter: ToastTime.DISMISSAFTER, size: 'large', containerClass: 'survey-action-toast' })` in `SurveyPublishPopupComponent.confirmPublish()` (L62), plus `router.navigateByUrl('/my-assets/survey')`. e2e locator text is "Survey published successfully" (no trailing period) — [surveyBuilder.locator.json](locators/survey/surveyBuilder.locator.json#L51).
- **Real backend?** Yes — `publishSurvey()` → `runReportService.runReport(true)` then `submitSurvey('/publish', ...)` → `httpClient.post(environment.apiUrls.surveyEntityServiceUrl + '/publish', payload, ...)` ([survey.service.ts](../libs/survey-mod-lib/src/lib/features/build-survey/services/survey.service.ts#L174-204)).
