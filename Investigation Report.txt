Findings — Product Offering tiles (dataset-selector.component.mjs, same file as before)
Source: dataset-selector.component.mjs (and identical content in the fesm2022 bundle).

There are two different tile renderings in this template, and neither one embeds the offering's identity in the data-test-id:

1. Regular "ALL" list tiles (the *ngFor loop, where both Omnishopper/Homescan will normally appear)

<ng-container *ngFor="
    let datasetBaseType of datasetBaseTypesList | removeFavouriteDefaults | sort : 'title';
    let i = index
  ">
  <div
    [ngClass]="selectedDatasetBaseType?.title === datasetBaseType?.title ? 'dataset-type-wrapper-selected' : 'dataset-type-wrapper'"
    [attr.data-test-id]="'rv-dataset-type-selector' + i"
    (click)="selectDatasetType(datasetBaseType)"
  >
    ...
    <h2 class="pl-0">{{ datasetBaseType?.title }}</h2>
    ...
data-test-id = 'rv-dataset-type-selector' + i, where i is the plain array index (let i = index) from the *ngFor, over the list after removeFavouriteDefaults and sort : 'title' (alphabetical by title).
i is not derived from datasetBaseType.title, .type, or .apiKey — it's a positional index only. The list is sorted alphabetically by title first, so ordering is deterministic given the same set of items, but the attribute itself carries zero identity information.
The only place either tile's real identity appears is the rendered text: <h2 class="pl-0">{{ datasetBaseType?.title }}</h2> — i.e. the visible label ("Panel On Demand Omnishopper" / "Panel On Demand Homescan"). datasetBaseType?.apiKey exists on the object but is only used to pick an icon (getNiqIconByApiKey(...)) — it's never written out as a DOM attribute.
2. "Default"/pinned source-type tile (shown above the list, only if one is marked default)
<div
  *ngIf="defaultSourceTypeObj"
  [ngClass]="defaultSourceType?.title === selectedDatasetBaseType?.title ? 'default-dataset-type-wrapper-selected' : 'default-dataset-type-wrapper'"
  (click)="selectDatasetType(defaultSourceType)"
>
  ...
  <h2 class="pl-0">{{ defaultSourceType?.title }}</h2>
  ...
This tile has no data-test-id attribute at all — only ngClass and click. Same story: the title text is the only distinguishing signal.
Direct answer to your question
Purely index-based, with no identity/name/type value in the data-test-id for either tile. The index (i) is just the post-sort position in the currently-rendered list, not tied to "Omnishopper" or "Homescan" specifically — and the default/pinned variant of this tile has no data-test-id at all. The only reliable way to distinguish the two tiles in the DOM is the visible h2.pl-0 text (Panel On Demand Omnishopper vs Panel On Demand Homescan), not any attribute.
