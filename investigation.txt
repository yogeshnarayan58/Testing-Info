GTA Migration Guide for Existing Users: GitLab to JFrog
This guide is for teams already using GTA from the old GitLab package flow and migrating to JFrog Artifactory.

Who Should Use This Guide
Use this if your existing project already consumes @gfk/gta and you need to switch package access to JFrog.

Migration Summary
Old source: GitLab package publishing/consumption flow
New source: JFrog Artifactory registries
Required action: update local environment + .npmrc + reinstall dependencies
Step 1: Request JFrog Access
Ensure you have a JFrog account: - https://artifactory.adlm.nielseniq.com/ui/packages
Log into jfrog application and check if you view the @gfk/gta library in it: https://artifactory.adlm.nielseniq.com/ui/repos/tree/General/dp-npm-prod-dp-local/@gfk/gta like given below:

If you are not able to view gta library like given above then raise access request to Data Platform: - https://adlm.nielsenconnect.com/jiraservicedesk/servicedesk/customer/portal/2/create/313 . 
In this form, enter the list of developer lan ids and set the team already have permission target to "Yes" and search and add "T-CONNECT_DataPlatform-dataplatform" from the dropdown box:

Confirm your account has entitlement to @gfk scoped packages, especially: - @gfk/gta - @gfk/azure-login
Step 2: Generate/Get Your JFrog Read Token
Obtain a JFrog personal access token/password with read permissions.
Keep this token private.
Use it as environment variable JFROG_RO_PASSWORD.
Step 3: Set Environment Variable
macOS/Linux (zsh/bash)


export JFROG_RO_PASSWORD="<your_jfrog_token>"
To persist in zsh:



echo 'export JFROG_RO_PASSWORD="<your_jfrog_token>"' >> ~/.zshrc
source ~/.zshrc
Windows PowerShell


setx JFROG_RO_PASSWORD "<your_jfrog_token>"
Open a new terminal after setx.

Step 4: Update .npmrc in Your Test Project
At the root of your GTA test project, use:



@gfk:registry=https://artifactory.adlm.nielseniq.com/artifactory/api/npm/dp-npm-prod-dp-local/
//artifactory.adlm.nielseniq.com/artifactory/api/npm/dp-npm-prod-dp-local/:_authToken=${JFROG_RO_PASSWORD}
registry=https://artifactory.adlm.nielseniq.com/artifactory/api/npm/npmjs-org-remote/
//artifactory.adlm.nielseniq.com/artifactory/api/npm/npmjs-org-remote/:_authToken=${JFROG_RO_PASSWORD}
Step 5: Clean Old Lock/Cache (Recommended)
From project root:



rm -rf node_modules
rm -f package-lock.json
npm cache verify
Step 6: Reinstall Dependencies


npm install
Step 7: Validate GTA Resolution from JFrog


npm view @gfk/gta version
npm view @gfk/azure-login version
Optional validation:



npm ls @gfk/gta
Step 8: Run a Smoke Test
Run one test command from your project, for example:



npm run playwright:sampleProject:api
or



npm run cucumber:sampleProject:api
Common Issues and Fixes
403 for @gfk/* packages
Possible cause: account entitlement issue in JFrog (even when token is valid).

Action:

Verify env var is set and non-empty.
Verify .npmrc is correct.
If still failing, request package entitlement for @gfk scope via JFrog/Data Platform support.
Token not picked up
Restart terminal/session.
Re-run echo $JFROG_RO_PASSWORD (macOS/Linux) or check env in PowerShell.
Re-run npm install.
Checklist for Existing GTA Projects
[ ] JFrog account available
[ ] Access request approved (if required)
[ ] JFROG_RO_PASSWORD configured
[ ] .npmrc updated to JFrog registries
[ ] Dependencies reinstalled
[ ] @gfk/gta resolves successfully
[ ] Smoke tests pass
Notes for Team Maintainers
Keep .npmrc in repo root so new joiners use a consistent registry setup.
Never commit real tokens in code, docs, or CI logs.
Share this page with teams migrating from older GitLab-based GTA setup.
