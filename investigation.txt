import { BasePage } from '@gfk/gta';
import { CommonPage } from '../common/common-page';
import { UI_STATE_UPDATE_DELAY, PANEL_TRANSITION_DELAY } from '../../constants/timeout-constants';
import { envConfig } from '../../config/env.config';

const SURVEY_BUILDER_PAGE_COMPONENT_NAME = 'surveyBuilderPage';
const MAX_QUESTIONS_TOOLTIP_TIMEOUT = 10 * 1000; // TC_BS_08 — tooltip may render in a portal after a short delay

/**
 * SurveyBuilderPage — covers the "Build Survey" screen: adding questions of each
 * type (TC_BS_03–TC_BS_09), review mode (part of TC_BS_13), and save/publish
 * (TC_BS_16).
 *
 * IMPORTANT ASSUMPTIONS / UNCONFIRMED ITEMS (verify against live DOM before
 * trusting these in CI):
 *
 * 1. `optionInputByLabel`/row/column inputs are resolved by role name + `nth=0`,
 * NOT scoped to a specific question. This only works reliably for the question
 * currently expanded/being edited (i.e. call these methods for one question at
 * a time, right after adding it, before adding the next). Once a question
 * collapses (per TC_BS_03 step 4), `reopenCollapsedQuestion()` (via
 * `editQuestionButton`, `[niqtooltip='Edit']`) re-expands it — confirmed present
 * via live DevTools inspection. UNCONFIRMED: `[niqtooltip='Edit']` is a single
 * static locator with no per-question scoping. Once more than one question has
 * collapsed on the page (from TC_BS_04 onward), this selector will match
 * multiple elements and is ambiguous — Playwright strict-mode will throw. A
 * live-DOM check of the collapsed-question container markup is needed to scope
 * this to the specific question (e.g. a per-question wrapper id/data-test-id)
 * before trusting it beyond the very first question.
 * 2. `requiredToggle` ([data-test-id='-input-checkbox']) is CONFIRMED correct per
 * real Codegen recording — the truncated id with no real prefix is how the
 * live DOM actually renders it.
 * 3. Point Scale's "+ Row"/"+ Column" buttons are CONFIRMED (via source, see
 * item 11) to share the exact same `survey-scale-editor` component and
 * matrix-actions hover mechanism as Multi Scale (`selectedType()` only toggles
 * radio-button vs checkbox cells, not the add-row/column controls) — the fix
 * applied to `addRowToQuestion()`/`addColumnToQuestion()` for Multi Scale
 * applies equally to Point Scale. `TC_BS_08` unblocked accordingly.
 * 4. No locator exists yet for the "Text" question type (TC_BS_06) — it was never
 * exercised in the Codegen capture. addTextQuestion() is NOT implemented here;
 * add it once a locator is confirmed.
 * 5. "Publish" is confirmed by the dev team (TC_BS_14, TC_BS_16) to currently be a
 * no-op with no validation. publishSurvey() below only performs the click —
 * callers should NOT assert a "published" outcome until backend support ships.
 * 6. The earlier "Build Survey" blur-click fix (`surveyBuilderBlurTarget`) was
 * REMOVED — a real test run confirmed the blur clicks fired successfully but
 * "Add option" still never became interactable. Root cause is the question
 * card collapsing/saving after a field fill, not just losing focus; the fix
 * is `reopenCollapsedQuestion()` (see item 1) instead of blurring.
 * 7. `ratingQuestionTextInput` is confirmed present via live DevTools inspection
 * for Rating's question-text field, but has NO confirmed per-question/index
 * scoping. Two different real DOM captures have been seen for it at different
 * times: a generic truncated attribute `[data-test-id='-input']`, and later a
 * numeric auto-generated `[id='text-field-80']`-style id (the latter is a
 * classic UI-library sequential-counter id — NOT deterministically tied to
 * the Rating question; its exact number depends on how many similar
 * components were instantiated earlier on the page, so it can silently point
 * at the wrong element between runs, which is the confirmed root cause of
 * TC_BS_05 "runs without error but nothing visibly typed"). Reverted to the
 * generic `data-test-id` attribute with a `:visible` filter appended (only the
 * currently-expanded question's field should be visible; a prior question's
 * collapsed field should not be) as a best-effort interim scoping — this is
 * NOT the index-based `${text}` pattern `questionTextInput` uses, because no
 * confirmed indexed/unique attribute exists for Rating's field yet. A fresh
 * live-DOM capture of Rating's text field specifically while a prior question
 * already exists on the page is needed to confirm a real indexed attribute
 * before this can match the `questionTextInput` pattern. `addRatingQuestion()`
 * does not accept/need a questionIndex at all, since this locator isn't index-based.
 * 8. `addOptionButton` (shared by `addSingleChoiceQuestion()` and
 * `addMultipleChoiceQuestion()` via `addOptionToQuestion()`) was a page-wide,
 * unscoped `text=` locator with no question-scoping — once a prior question
 * already exists on the page (e.g. TC_BS_04 running after TC_BS_03), its
 * "Add option" control resolves to 2 elements and Playwright strict-mode
 * throws. Reverted to the previously-confirmed `niq-button:has-text('Add
 * option')` form with a `:visible` filter appended, same interim mitigation
 * technique as item 7 — assumes a prior (collapsed) question's control isn't
 * visible. Not independently re-confirmed live.
 * 9. `addMultipleChoiceQuestion()`, `addRatingQuestion()`, `addNPSQuestion()`, and
 * `addMultiScaleQuestion()` all now call the existing `clickAddQuestion()`
 * (reusing `addQuestionLink`) at the end, to finalize/save the question (manual
 * click confirmed live to unblock the flow for Multiple Choice → Rating). RISK:
 * `survey-builder.spec.ts` ALSO still calls `clickAddQuestion()` separately
 * before each of `addRatingQuestion()` (TC_BS_05) and `addNPSQuestion()`
 * (TC_BS_07) — "Add question" is clicked twice in a row at each of those
 * transitions, which likely creates an extra blank question each time. Not
 * resolved here since it requires editing the spec file, out of scope for
 * these fixes — needs an explicit follow-up decision on removing the redundant
 * external calls. `addMultiScaleQuestion()` does NOT have this same double-click
 * risk today since no test currently runs after TC_BS_09 that calls
 * `clickAddQuestion()` again.
 * 10. `addNPSQuestion()` fills NPS's question text via the SHARED
 * `questionTextInput` resource (same index-based locator Single/Multiple
 * Choice use: `[data-test-id='question-text-input-${text}-input']`) — CONFIRMED
 * correct via live DevTools inspection: `<input data-test-id="question-text-
 * input-4-input" placeholder="Question">`, matching the live-rendered index at
 * the time of that capture. See item 12 — this index is now computed
 * dynamically rather than passed in by the caller.
 * 11. `addRowToQuestion()`/`addColumnToQuestion()` (Point Scale/Multi Scale):
 * per `e2e/SURVEY_BUILDER_HOVER_INVESTIGATION.md`, the real Angular source
 * (`libs/survey-mod-lib/.../scale-editor.component.html`) confirmed the "Row"/
 * "Column" buttons only exist in the DOM once the WRAPPING `.matrix-action-area`
 * div's `mouseenter` sets `showAddMenu = true` — hovering the button itself
 * (the earlier fix) could never work, and there is NO CSS transition to delay
 * for, so the delay-based mitigation was removed. Now hovers `scaleAddMenuTrigger`
 * (`.matrix-action-area:has(niq-icon-button[iconname='add-large'])`) first,
 * then resolves `addRowButton`/`addColumnButton` SCOPED WITHIN that same
 * wrapper (via `WebElement.getWebElement()` chaining) so the Add menu's
 * buttons are targeted, not the Delete menu's identically-labeled ones.
 * UNCONFIRMED: this has NOT been run against the live app yet. Also: `.last()`
 * does NOT exist on this codebase's `WebElement` API (confirmed by reading
 * `@gfk/gta`'s webElement.d.ts) and `editQuestionButton` does NOT actually use
 * any such pattern today (it has a known, still-open, unscoped-selector risk —
 * see item 1) — so `scaleAddMenuTrigger` uses the same `:visible` interim
 * scoping already used for `ratingQuestionTextInput`/`addOptionButton` (items
 * 7-8) instead, which has the same residual multi-question-on-page risk.
 * 12. `questionIndex` is NO LONGER a caller-supplied literal. Per
 * `question-editor.component.ts`'s `upcomingQuestionNumber = surveyService
 * .getQuestions().length + 1`, the real index for a new question is always
 * `(current saved question count) + 1`, computed live — not a fixed sequence
 * number — because the persisted survey's question count isn't stable across
 * runs (manual testing, partial failures, etc. can leave it with more/fewer
 * questions than the test suite assumes). Hardcoded indices (TC_BS_08 was
 * tried as 6, then 7; the live value was actually 5) are a structural bug
 * class, not a one-off typo. `getNextQuestionIndex()` now counts the
 * rendered `.question-number` markers (`questionNumberMarker` resource) on
 * already-saved questions and returns `count + 1`, mirroring the app's own
 * computation. Every `addXQuestion()` method calls this internally; none of
 * them accept a `questionIndex` parameter anymore.
 */
export class SurveyBuilderPage extends CommonPage {
  constructor(basePage: BasePage) {
    super(basePage);
    this.resourceManager.registerResources(
      SURVEY_BUILDER_PAGE_COMPONENT_NAME,
      surveyBuilderPageResources
    );
  }

  // Question type selection
  private async clickQuestionTypeResource(resourceName: string): Promise<void> {
    const typeButton = this.webActionHandler.getWebElement(
      this.resourceManager.getResource(resourceName, SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await typeButton.waitFor();
    await typeButton.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  // Shared field helpers (operate on the currently expanded/editing question)
  private async fillQuestionText(questionIndex: number, text: string): Promise<void> {
    const questionText = this.webActionHandler.getWebElement(
      this.resourceManager.getDynamicResource('questionTextInput', String(questionIndex), SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await questionText.waitFor();
    await questionText.enterText(text);
  }

  /** Fills Option N / Row N / Column N fields by their visible role label, e.g. 'Option 1', 'Row 2'. */
  private async fillLabeledField(label: string, value: string): Promise<void> {
    const field = this.webActionHandler.getWebElement(
      this.resourceManager.getDynamicResource('optionInputByLabel', label, SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await field.waitFor();
    await field.enterText(value);
  }

  /** Fills Rating's question-text field — see class-level comment #7 for the unscoped-locator risk. */
  private async fillRatingQuestionText(text: string): Promise<void> {
    const questionText = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('ratingQuestionTextInput', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await questionText.waitFor();
    await questionText.enterText(text);
  }

  /**
   * Computes the questionIndex for a new question the same way the app itself does:
   * `surveyService.getQuestions().length + 1` (see question-editor.component.ts's
   * `upcomingQuestionNumber`). Counts the rendered `.question-number` markers on
   * already-saved questions rather than trusting any hardcoded literal, since the
   * persisted survey's question count is not stable across runs.
   */
  private async getNextQuestionIndex(): Promise<number> {
    const markers = await this.webActionHandler.getWebElementsText(
      this.resourceManager.getResource('questionNumberMarker', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    return markers.length + 1;
  }

  /** Counts rendered `.question-number` markers, for TC_BS_REVIEW_MODE's delete-count assertion. */
  async getQuestionCount(): Promise<number> {
    const markers = await this.webActionHandler.getWebElementsText(
      this.resourceManager.getResource('questionNumberMarker', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    return markers.length;
  }

  /** Re-expands the question card after it collapses/saves on field-fill — see class-level comment #1.
   *  `editQuestionButton` ([niqtooltip='Edit']) matches one icon per question, so once 2+ questions
   *  exist it's a Playwright strict-mode violation; scope to the LAST match (the question just added). */
  private async reopenCollapsedQuestion(): Promise<void> {
    const questionCount = await this.getQuestionCount();
    const editButtonResource = this.resourceManager.getResource('editQuestionButton', SURVEY_BUILDER_PAGE_COMPONENT_NAME);
    const editButton = this.webActionHandler.getWebElement({
      ...editButtonResource,
      selectorType: 'playwrights',
      selectorValue: `${editButtonResource.selectorValue} >> nth=${Math.max(questionCount - 1, 0)}`
    });
    await editButton.waitFor();
    await editButton.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  async addOptionToQuestion(): Promise<void> {
    const addOption = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('addOptionButton', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await addOption.waitFor();
    await addOption.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  /** Hovers the Add-menu trigger wrapper so the Row/Column buttons render — see class-level comment #11. */
  private async hoverScaleAddMenuTrigger() {
    const addMenuTrigger = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('scaleAddMenuTrigger', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await addMenuTrigger.waitFor();
    await addMenuTrigger.hover();
    return addMenuTrigger;
  }

  /** UNCONFIRMED for Point Scale — see class-level comment #3. */
  async addRowToQuestion(): Promise<void> {
    const addMenuTrigger = await this.hoverScaleAddMenuTrigger();
    const addRow = addMenuTrigger.getWebElement(
      this.resourceManager.getResource('addRowButton', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await addRow.waitFor();
    await addRow.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  /** UNCONFIRMED for Point Scale — see class-level comment #3. */
  async addColumnToQuestion(): Promise<void> {
    const addMenuTrigger = await this.hoverScaleAddMenuTrigger();
    const addColumn = addMenuTrigger.getWebElement(
      this.resourceManager.getResource('addColumnButton', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await addColumn.waitFor();
    await addColumn.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  /** UNCONFIRMED locator — see class-level comment #2. Do not rely on this without a live DOM check. */
  async toggleRequired(): Promise<void> {
    const toggle = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('requiredToggle', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await toggle.waitFor();
    await toggle.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  /** TC_BS_12 — footer's "Back" button (footer.component.html), no data-test-id, resolved by text. */
  async clickBackButton(): Promise<void> {
    const backButton = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('backButton', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await backButton.waitFor(10000);
    await backButton.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  /** TC_BS_12 — stepper's clickable circle (niq-step-circle, athena-core StepComponent), text doesn't navigate; index 0 = Select Panelists. */
  async clickSelectPanelistsStep(): Promise<void> {
    const step = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('select-panelists-step-circle', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await step.waitFor(10000);
    await step.click();
    await this.webActionHandler.delay(UI_STATE_UPDATE_DELAY);
  }

  async clickAddQuestion(): Promise<void> {
    const addQuestion = this.webActionHandler.getWebElement(
      this.resourceManager.getResource('addQuestionLink', SURVEY_BUILDER_PAGE_COMPONENT_NAME)
    );
    await addQuestion.waitFor();
    await addQuestion.click();
    await this.webActionHandler.delay(PANEL_TRANSITION_DELAY);
  }

  // ---------------------------------------------------------------------
  // Per-question-type methods (TC_BS_03–TC_BS_09)
  // Each assumes it is called right after clickAddQuestion() (or for
  // question 1, right after landing on Build Survey), while this question
  // is the currently expanded one.
  // ---------------------------------------------------------------------

  /** TC_BS_03 */
  async addSingleChoiceQuestion(questionText: string, options: string[]): Promise<void> {
    try {
      const questionIndex = await this.getNextQuestionIndex();
      await this.clickQuestionTypeResource('questionTypeSingleChoice');
      await this.fillQuestionText(questionIndex, questionText);
      for (let i = 0; i < options.length; i++) {
        if (i >= 2) {
          await this.reopenCollapsedQuestion();
          await this.addOptionToQuestion();
        }
        await this.fillLabeledField(`Option ${i + 1}`, options[i]);
      }
    } catch (error) {
      throw new Error(`Failed to add Single Choice question: ${error instanceof Error ? error.message : error}`);
    }
  }

  /** TC_BS_04 */
  async addMultipleChoiceQuestion(questionText: string, options: string[]): Promise<void> {
    try {
      const questionIndex = await this.getNextQuestionIndex();
      await this.clickQuestionTypeResource('questionTypeMultipleChoice');
      await this.fillQuestionText(questionIndex, questionText);
      for (let i = 0; i < options.length; i++) {
        if (i >= 2) {
          await this.addOptionToQuestion();
        }
        await this.fillLabeledField(`Option ${i + 1}`, options[i]);
      }
      await this.clickAddQuestion(); // finalizes/saves this question, see class-level comment #9 for the double-click risk this introduces
    } catch (error) {
      throw new Error(`Failed to add Multiple Choice question: ${error instanceof Error ? error.message : error}`);
    }
  }

  /** TC_BS_05 */
  async addRatingQuestion(questionText: string): Promise<void> {
    try {
      await this.clickQuestionTypeResource('questionTypeRating');
      await this.fillRatingQuestionText(questionText); // Rating's input is unscoped by index, see class-level comment #7
      await this.clickAddQuestion(); // finalizes/saves this question, see class-level comment #9 for the double-click risk this introduces
    } catch (error) {
      throw new Error(`Failed to add Rating question: ${error instanceof Error ? error.message : error}`);
    }
  }

  /**
   * TC_BS_06 — NOT IMPLEMENTED. No confirmed locator for the "Text" question
   * type exists yet (never exercised in the Codegen capture). Add this once
   * `questionTypeText` is confirmed and added to survey-builder.locator.json.
   */
  // async addTextQuestion(questionIndex: number, questionText: string): Promise<void> { ... }

  /** TC_BS_07 */
  async addNPSQuestion(questionText: string): Promise<void> {
    try {
      const questionIndex = await this.getNextQuestionIndex();
      await this.clickQuestionTypeResource('questionTypeNPS');
      await this.fillQuestionText(questionIndex, questionText); // confirmed via DevTools: NPS reuses questionTextInput at this index, see class-level comment #10
      await this.clickAddQuestion(); // finalizes/saves this question, see class-level comment #9 for the double-click risk this introduces
    } catch (error) {
      throw new Error(`Failed to add Net Promoter Score question: ${error instanceof Error ? error.message : error}`);
    }
  }

  /**
   * TC_BS_08 — Point Scale. Shares the exact same `survey-scale-editor` Angular
   * component (and matrix-actions hover mechanism) as Multi Scale — confirmed
   * via source, see class-level comment #11.
   */
  async addPointScaleQuestion(
    questionText: string,
    rows: string[],
    columns: string[]
  ): Promise<void> {
    try {
      const questionIndex = await this.getNextQuestionIndex();
      await this.clickQuestionTypeResource('questionTypePointScale');
      await this.fillQuestionText(questionIndex, questionText);
      for (let i = 0; i < rows.length; i++) {
        if (i >= 2) {
          await this.addRowToQuestion();
        }
        await this.fillLabeledField(`Row ${i + 1}`, rows[i]);
      }
      for (let i = 0; i < columns.length; i++) {
        if (i >= 2) {
          await this.addColumnToQuestion();
        }
        await this.fillLabeledField(`Column ${i + 1}`, columns[i]);
      }
      await this.clickAddQuestion(); // finalizes/saves this question, see class-level comment #9 for the double-click risk this introduces
    } catch (error) {
      throw new Error(`Failed to add Point Scale question: ${error instanceof Error ? error.message : error}`);
    }
  }

  /** TC_BS_09 — Multi Scale, including add-row/add-column (confirmed real per Codegen + TC_BS_09). */
  async addMultiScaleQuestion(
    questionText: string,
    rows: string[],
    columns: string[]
  ): Promise<void> {
    try {
      const questionIndex = await this.getNextQuestionIndex();
      await this.clickQuestionTypeResource('questionTypeMultiScale');
      await this.fillQuestionText(questionIndex, questionText);
      for (let i = 0; i < rows.length; i++) {
        if (i >= 2) {
          await this.addRowToQuestion();
        }
        await this.fillLabeledField(`Row ${i + 1}`, rows[i]);
      }
      for (let i = 0; i < columns.length; i++) {

          await this.addColumnToQuestion();

    } catch (error) {
      throw new Error(`Failed to add Multi Scale question: ${error instanceof Error ? error.message : error}`);

## Structural Fix: Dynamic `questionIndex` Replaces Hardcoded Literals — 2026-10-01

### Why hardcoded indices were fragile

Confirmed via source (`libs/survey-mod-lib/.../question-editor/question-editor.component.ts`):

```ts
displayQuestionNumber = computed(() =>
  this.questionNumber() ?? this.upcomingQuestionNumber
);

get upcomingQuestionNumber(): number {
  return this.surveyService.getQuestions().length + 1;
}
```

`question-type-selector.component.html` (used while a new question is being
created) never binds `[questionNumber]`, so this fallback always applies to
a newly-added question: its real index is **`(current saved question count)
+ 1`, computed live** — not a fixed sequence number derivable from test
order. Because `survey-builder.spec.ts` tests run against a single,
persisted "Automation Test Survey," the saved question count is not stable
across runs (manual test sessions, partial failures, or stray leftover
questions can all shift it). This is exactly why `TC_BS_08`'s hardcoded
index was tried as `6`, then `7`, while the live value was actually `5`
(see `SURVEY_BUILDER_INVESTIGATION_POINT_SCALE_V2.md`) — and why NPS/Multi
Scale hit the same class of bug earlier. Any hardcoded literal is a
structural risk, not a one-off wrong number.

### Fix applied

1. **New locator** `questionNumberMarker` added to
   `surveyBuilder.locator.json` (`selectorType: "css"`, `selectorValue:
   ".question-number"`) — matches the Angular source's rendered marker for
   each already-saved (collapsed) question, regardless of question type.
2. **New private helper** `getNextQuestionIndex()` on `SurveyBuilderPage`,
   using the already-available `webActionHandler.getWebElementsText()`
   (returns `Promise<string[]>` for all matching elements — an existing
   GTA API, no new locator/counting strategy invented) to count currently
   rendered `.question-number` markers and return `count + 1`, mirroring
   the app's own `upcomingQuestionNumber` computation.
3. **All six `addXQuestion()` methods** (`addSingleChoiceQuestion`,
   `addMultipleChoiceQuestion`, `addRatingQuestion`, `addNPSQuestion`,
   `addPointScaleQuestion`, `addMultiScaleQuestion`) no longer accept a
   `questionIndex` parameter. Each method that needs it now computes
   `questionIndex` internally via `getNextQuestionIndex()` at the top of
   its `try` block, right before filling the question-text field.
   (`addRatingQuestion()` never used the index at all — its text field
   locator isn't index-based — so it simply dropped the unused parameter.)
4. **`survey-builder.spec.ts`** — every TC_BS_03/04/05/07/08/09 call site
   dropped the hardcoded index argument, including removing the stale
   `// index 7, not 6: an extra manually-added question already occupies
   slot 6...` comment on the Point Scale call.

### Why this resolves the bug class

The persisted survey's question count can no longer silently diverge from
what the test suite assumes — each `addXQuestion()` call now reads the
actual live count off the DOM immediately before using it, self-correcting
for any leftover/stray questions instead of requiring a human to keep
re-guessing a literal after every run.

        }

      }
      await this.clickAddQuestion(); // finalizes/saves this question, see class-level comment #9 for the double-click risk this introduces
    } catch (error) {
      throw new Error(`Failed to add Point Scale question: ${error instanceof Error ? error.message : error}`);
    }
  }
